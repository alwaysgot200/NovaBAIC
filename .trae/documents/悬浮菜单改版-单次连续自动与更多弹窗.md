# 悬浮球子菜单改版方案：单次 / 连续 / 自动 / 主界面 / 更多 / 退出

## 1. 背景与目标

用户要求优化悬浮球扇形子菜单：

1. 「问答」改为「**单次**」——单击执行单次参谋（= 长按主球，现有 `startOneShot()`，仅改名）
2. 新增「**连续**」——单击执行连续参谋（= 双击主球，现有 `startRecording()`）
3. 「**自动**」——自动托管模式，基于**关联联系人的聊天会话所设定的 APP**：感知面是聊天 APP 的**通知**（以及后续的定时打开 APP 巡查），与当前屏幕无关
4. 第四项「**主界面**」（现有 `showMainUi()`，仅挪位置）
5. 第五项「**更多**」——弹出列表菜单：设置 / 帮助 / 老参谋设置 / 联系人画像，右上角 ✕ 关闭
6. 「退出」经用户确认**保留为第 6 项**（扇形仍 6 项，几何参数 ±75°/30° 分度完全不变）

「更多」弹窗与「自动」选择器均经用户确认采用**悬浮球旁小卡片**样式，跟随球位置、贴屏边保护。

**三种模式的概念定位（用户定调，2026-10-22）**：

| 模式 | 感知对象 | 前提 |
| --- | --- | --- |
| 单次 / 连续 | **当前屏幕**显示的内容（当前屏幕可能根本不是一个聊天 APP） | 投影/无障碍截屏 |
| 自动托管 | 关联联系人 × 各自聊天会话设定的 APP 的**聊天通知**（Phase 2 增加定时打开 APP 巡查新消息） | 必须已有"联系人 ↔ APP 聊天会话"关联（chat_channels），否则无从监控 |

因此「自动」入口带**就绪门**：本机没有任何关联联系人，或有关联联系人但没有任何关联 APP 聊天会话时，弹提示「**本机尚未关联任何APP，无法执行自动托管**」并引导去联系人画像页建立关联，不进选择器。

## 3. 改动方案

### 3.1 扇形菜单项改版（FloatBallService.expandMenu + strings）

新 6 项（上→下，与 offsets -75°…+75° 对应）：

| 序 | 新文案 | 动作 | 说明 |
| --- | --- | --- | --- |
| 1 | 单次 | `startOneShot()` | 原「问答」，动作不变 |
| 2 | 连续 | `startRecording()` | 新增项，= 双击主球 |
| 3 | 自动 | `openAutoScopePicker()` | 新增：弹出范围选择小窗（见 3.3） |
| 4 | 主界面 | `showMainUi()` | 挪位 |
| 5 | 更多 | `openMoreMenu()` | 新增：弹出列表菜单（见 3.2） |
| 6 | 退出 | `exitApp()` | 不变 |

- strings：新增 `float_fan_oneshot`(单次)、`float_fan_continuous`(连续)、`float_fan_more`(更多)；`float_fan_ask`(问答) 无他处引用后删除；「自动」沿用现有 `float_split_auto`。
- 「自动」原直接 `startCompanionWindow()`（对当前绑定联系人），改为先进范围选择器。
- 同步更新类头注释（L82-90 交互模型）与 expandMenu KDoc 中的菜单清单。

### 3.2 「更多」弹窗（FloatUi 新工厂 + Service 接线）

- `FloatUi.buildListMenu(...)`：纯视觉小卡片（圆角、Baic2 风格深色面板，与扇形子球同色系）：
  - 标题行「更多」 + 右上角 ✕ 关闭按钮
  - 4 行列表：设置 / 帮助 / 老参谋设置 / 联系人画像
- `FloatBallService.openMoreMenu()`：参照 menuView/menuParams 模式挂 overlay 窗，位置跟随主球（贴左半屏向右弹、贴右半屏向左弹，钳制屏内），点外部或 ✕ 关闭。
- 行动作复用现有方法：设置=`openMainSettings()`、帮助=`openHelp()`、老参谋设置=启动 `FloatSettingsActivity`（NEW_TASK）、联系人画像=启动 `AdvisorProfileActivity`（NEW_TASK，无 extras）。
- `hideAllOverlays()` / `removeAllOverlays()` / `dismissMenuNow()` 同步清理该窗口（防残留僵尸窗 + 防 OCR 自噬）。

### 3.3 「自动」自动托管入口：就绪门 + 范围选择弹窗

`FloatUi.buildScopePicker(...)`（纯视觉）+ `FloatBallService.openAutoScopePicker()`（接线），同 3.2 窗口管理。

**第一步·就绪门（点「自动」立即校验，不满足则不进选择器）**：
- 查询 `ContactRepository`：本机没有任何关联联系人，**或**有联系人但 `chat_channels` 总数为 0 → 弹提示「**本机尚未关联任何APP，无法执行自动托管**」（toast 或小卡片提示，含"去建立关联"引导 → 联系人画像页），流程终止。
- 自动托管的监控对象 = 关联联系人 × 其聊天会话设定的 APP（`chat_channels`）；没有关联即无从监控。

**第二步·范围选择器（就绪门通过后弹出）**：

- 顶部行「**全部联系人**」：监控所有**已关联 APP 会话**的联系人，在所有已关联 APP 的未读来信。
- 联系人列表：**只列名下有 `chat_channels` 的联系人**（无任何 APP 关联的联系人不进自动托管范围）；点按展开二级 = 「所有 APP」+ 该联系人名下各 `chat_channels`（显示 APP 名 + 会话名）。

**选定范围后的接线（感知面 = 聊天 APP 通知，复用现有引擎）**：

| 选择 | Phase 1 行为 |
| --- | --- |
| 联系人 X + 具体会话（某 APP） | `ImChatNavigator` 自动打开该聊天页 → `beginCompanion(X)` 陪伴窗口自动参谋（拟回 + Gatekeeper 硬审后受控自动发送）；该 APP 后台新来信由通知监听触发拟稿 |
| 联系人 X + 所有 APP | 默认取最近会话打开 → 陪伴窗口；其余 APP 的来信由**通知监听**感知并拟稿提醒（多 APP 并行监控） |
| 全部联系人 | 开启通知拟稿模式（`draftEnabled`）：所有关联联系人在所有关联 APP 的未读来信自动拟稿+通知主人；**陌生/未建档来信不再静默忽略，改为"陌生来信"通知主人（仅通知，不消耗 LLM、绝不自动回复陌生人）** |
| （任何范围） | 通知监听未开启时引导去系统设置开启（通知是 Phase 1 唯一感知面，不开则自动托管无感知来源） |

- 白名单：选定联系人不在自动白名单时自动加入（容量 5，满则 toast 报因并引导去老参谋设置）。
- 安全边界保持现有设计：自动发送仅限陪伴窗口单联系人范围 + Gatekeeper 硬审（金钱/承诺/敏感内容降级为起草通知）；「全部联系人」模式 Phase 1 只拟稿+通知，不自动发送。
- **定时打开 APP 巡查新消息**（不依赖通知的第二感知面）属引擎扩展，Phase 2 交付（见 §4）。

### 3.4 director 小改：陌生来信通知

`AdvisorNotificationListener.handleDraftTurn`（L111-142）：联系人解析为 null 时由「静默忽略」改为发「陌生来信」通知（内容=APP 名 + 发信人标题 + 正文摘要，点击打开分屏预览）；复用现有节流（`shouldDispatch`）防轰炸。不自动建档、不 LLM 拟稿。

### 3.5 文案同步（strings.xml）

- 新增：`float_auto_no_apps`（「本机尚未关联任何APP，无法执行自动托管」就绪门提示）、`float_auto_scope_all`（全部联系人）、`float_auto_scope_apps_all`（所有 APP）、`float_more_title`（更多）等选择器/弹窗键
- `float_help_gesture_tap`：菜单清单改为「(单次 / 连续 / 自动 / 主界面 / 更多 / 退出)」
- `float_help_oneshot_body`：触发方式改「长按（或菜单「单次」）」
- `float_help_auto_body`：改为「自动托管 = 监控关联联系人在其关联 APP 的聊天通知；入口：菜单「自动」→ 选择联系人/APP 范围后开启；无关联 APP 时无法使用」口径，并说明单次/连续与自动托管的区别（前者看当前屏幕，后者看聊天通知）
- 其余帮助段落（连续参谋/自动参谋安全底线等）不动。

## 4. 不做与后续（Phase 2，另行出方案文档）

以下属成规模引擎扩展，本轮**不做**，待本菜单改版验收后单独出方案：
- **定时打开 APP 巡查新消息**：不依赖通知的第二感知面（定时用 ImChatNavigator 逐个打开关联会话截图巡查未读，通知不可用/被 ROM 拦截时的兜底）
- 「全部联系人」模式下的**多联系人自动发送**编排（需按联系人维度的 Gatekeeper 策略与风控）
- 陌生人自动建档/自动回复策略
- 公众号/服务号/系统通知的精细过滤（Phase 1 陌生来信通知可能包含少量噪音，靠节流兜底）
