## 二、总体设计原则

1. **数据不出端**：统计/漂移全在本地 DB 与内存态完成，不新增网络调用、不落任何遥测。
2. **零新增 LLM 成本**：G1/G2 均为纯函数+查询；G3 只是把已有回合态数据透出到 UI。
3. **绝不静默自动**：漂移检测只出建议条，人拍板（与 L1 完成建议同口径）；统计反哺只用
   固定中文模板，不做 LLM 自由文本（防提示词污染）。
4. **卡片式 UI**（用户偏好）：统计一律卡片/胶囊，不用表格。
5. **每步独立可编译、可提交**；改 strings.xml 只追加 float_* 键。

### F1：策略效果统计 + 反哺提示词（StatsFeedback；对应 G1）

**目标**：把「最近参谋建议执行得怎么样」变成可见数字，并让 LLM 知道自己的近期表现、
自我收敛（数据不出端）。

**数据源**（全本地）：
- `talk_missions`（每联系人/会话滚动 60 条，DAO 已有 trim）：`adoptedIndex` 采纳标记、
  结果 status（成功/失败/忽略）、mission 文本、scenarioCode；
- `stage_states.failStreak`、`stage_history`（跃迁轨迹）。

**统计核心**（新增纯函数 object `StrategyStatsCalculator`，advisor/strategy/ 包）：

```kotlin
data class StrategyStats(
    val total: Int, val adopted: Int, val succeeded: Int, val failed: Int,
    val failStreak: Int,
    val summary: String?,   // 固定模板复盘文本；total<10 时 null
)
fun calculate(missions: List<TalkMissionEntity>, failStreak: Int, now: Long): StrategyStats
```

- 窗口：最近 20 条**已判定**任务令（成功/失败；忽略不进分母）；
- 采纳率 = adoptedIndex≠null / total；成功率 = succeeded / total；
- `summary` 固定模板（三档，不做自由文本）：
  - 良好（成功≥70%）：「近期建议执行顺利，保持当前节奏与分寸」；
  - 一般：「近期建议约半数被执行，注意更贴合对方状态」；
  - 偏低（成功<40% 或 failStreak≥3）：「近期多番受挫，建议收敛主张、先共情再表达、降低推进强度」。

**展示**（两处，卡片式）：
1. **GoalTab 策略卡入口行**下追加一行统计小字（bodySmall/onSurfaceVariant）：
   「近20回合 · 采纳 45% · 成功 70%」（数据不足 10 条时整行隐藏）；
2. **StrategyCardActivity 顶部统计卡**：Surface 卡片内三枚胶囊（采纳率/成功率/当前
   连挫），下挂 summary 复盘句。

**反哺提示词**：
- `StrategyPrompt` 策略段末尾追加「近期复盘」小块：仅**增强档**注入 summary（智能档
  保持纯净控噪声）；`total<10` 不注入；
- 注入位置在策略卡块之后、红线块之前（与战术约束同区，物理顺序：策略卡 → 战术约束 →
  近期复盘 → 红线）。

**strings.xml 新键**：
```xml
<string name="float_stats_recent_line">近%1$d回合 · 采纳 %2$d%% · 成功 %3$d%%</string>
<string name="float_stats_adopt_rate">采纳率</string>
<string name="float_stats_success_rate">成功率</string>
<string name="float_stats_fail_streak">当前连挫</string>
<string name="float_stats_recap_title">近期复盘</string>
```

**单测**（新增 `app/src/test/.../strategy/StrategyStatsTest.kt`，纯 JVM）：
窗口裁剪（忽略不入分母）、除零（total=0 → summary=null）、三档 summary 边界（70%/40%）、
failStreak 透传、<10 条 null。

**改动文件**：新增 StrategyStatsCalculator.kt + StrategyStatsTest.kt；
修改 GoalRepository.kt（stats 查询）、GoalTab.kt（统计行）、StrategyCardActivity.kt（统计卡）、
StrategyPrompt.kt（反哺段）、ScreenAdvisor.kt（增强档取数注入）、strings.xml。

### F2：目标漂移检测（GoalDrift；对应 G2）

**目标**：任务令长期跑偏于当前 active L1 判据时，GoalTab 出黄条提醒用户修订目标
——目标体系「有生有灭有修正」闭环的最后一块。

**检测**（新增纯函数 object `GoalDriftDetector`，advisor/strategy/ 包）：

```kotlin
data class DriftVerdict(val drifted: Boolean, val consecutive: Int)
fun detect(
    l1Criteria: String, missionTexts: List<String>, l1CreatedAt: Long, now: Long,
): DriftVerdict
```

- 算法：`MemoryText.terms`（既有纯函数）对「L1 判据词集」与每条 mission 词集求交集；
- 判定条件（全部满足）：①该 L1 已创建 ≥3 天；②最近连续 ≥6 条 mission 与判据**零交集**；
  ③mission 样本 ≥6 条（不足不判）；
- 判据为空 / L1 非激活 → 永不判定（不臆测）。

**交互**（GoalTab，对应 L1 卡顶部）：
- 黄条：「任务令疑似偏离该目标：连续 %1$d 回合未指向目标判据」
  【调整目标】（打开既有编辑对话框）【忽略】；
- 【忽略】→ 复用 `dismissedL1Completions` 同款**内存抑制**（本进程生命周期内该 L1
  不再提示）；**绝不自动修改/降级目标**（与 L1 完成建议同口径：只建议、人拍板）；
- 同一时刻只对当前 active L1 判定（≤3 条 L1 中取 active）。

**strings.xml 新键**：
```xml
<string name="float_drift_title">目标漂移提醒</string>
<string name="float_drift_hint">任务令疑似偏离该目标：连续 %1$d 回合未指向目标判据，考虑修订目标或判据</string>
<string name="float_drift_fix">调整目标</string>
```

**单测**（新增 `GoalDriftTest.kt`，纯 JVM）：零交集判定、3 天门槛、样本不足不判、
空判据不判、连续计数在命中交集时清零。

**改动文件**：新增 GoalDriftDetector.kt + GoalDriftTest.kt；修改 GoalRepository.kt
（检测调用+抑制集）、GoalTab.kt（黄条）、strings.xml。

## 四、决策：不立项项（请知悉，可否决）

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 同一 L2 多路线假设并行与裁决（P2 §十四②） | **不立项** | 需并行双 roadmap 状态机+裁决器，复杂度高；有向图+reroute 换线+私有支线已覆盖「换路线」主需求。若用户坚持「最大化」，可作为后续独立方案再评估 |
| 思考链「单步纠偏」（P2 §十四③ 后半） | **不立项** | 纠偏对象应是主输出而非预调用产物；增强档预调用失败本就静默回退一段式，对 brief 纠偏价值存疑 |
| 多参与者群模型 | **不立项** | P3 范围口径用户已拍板「群=单一对方」；P5 群成员二级画像已交付更细粒度 |
| L1 自动完成 | **永不立项** | 设计红线（P3 §十：绝不自动勾选） |
