# 聊天策略裁量层方案 v2（多子代理协作：Strategist 策略官转正）

v2（2026-10-21）。按用户指令重写 v1：本系统全面对齐多子代理协作架构
（编排者按阶段调度专家子代理，各代理单职责、结构化交接物、失败可降级）；
「目标导向的手段策略」必须由**独立子代理**承担。v1 的 D2（Responder 一体化
自评）作废；存储/UI/红线/裁量三问沿用 v1。

> 铁律不变：红线死清单（§八）任何档位绝对禁止；模型只能提案，代码执法。

## 一、岗位总图（子代理归属：谁管哪个阶段）

一回合事务按阶段拆给九个岗位，每个岗位有唯一代码实体、唯一交接物、
唯一失败降级——无归属的事务不进管线：

| #   | 阶段事务                 | 子代理岗位                    | 代码实体（现状）                            | 交接物（结构化）     | 失败降级           |
| --- | ------------------------ | ----------------------------- | ------------------------------------------- | -------------------- | ------------------ |
| 1   | 屏幕感知                 | 感知官 Perceiver              | ScreenPerceiver / FrameDiffEngine           | 感知帧（Text/Image） | 阶梯降级→投影      |
| 2   | 来信判定                 | 门房合议团 ExpertPanel        | ExpertPanel + privacy/五件套（F1）          | IncomingReview       | 词表备胎/uncertain |
| 3   | 路由决策                 | Director                      | DirectorRoutes.route\*                      | Route 决策           | noop               |
| 4   | 场景与联系人归属         | 场景官 SceneGate              | SceneGate / EntityResolver                  | 场景+联系人档案      | NON_CHAT 保守      |
| 5   | **本回合方针与手段许可** | **策略官 Strategist（新建）** | floatball/experts/strategist/               | **Permit 许可单**    | 保守禁用（§3.5）   |
| 6   | 话题与素材               | 话题官                        | TopicEngine / TopicPlanner / WarmChatPrompt | 话题+素材稿          | 四源回退           |
| 7   | 稿件生成                 | 代言者 Responder              | AdvisorResponder + ChatBriefBuilder         | Draft 草稿           | 直连通道兜底       |
| 8   | 稿件审查                 | 审查官 Gatekeeper             | Gatekeeper（+T1 扩展越许可检测）            | Review（放行/降级）  | 降级起草不丢稿     |
| 9   | 发送与通报               | 执行官+联络官                 | ActionDispatcher / EscalationNotifier       | 发送结果/通知        | 起草通知           |
| 10  | 记忆沉淀与对账           | 档案官+简报官                 | 画像萃取 / BriefCompiler                    | 画像/周报            | 静默丢弃不阻塞     |

协作纪律（对齐专家合议团既有六条铁律）：

- 子代理只出**裁决/许可/草稿**，不执行动作（发送、通知、写库归执行面）；
- 子代理之间禁止互相 import（共享领域模型除外），编排只经唯一门面；
- N 件事 ≠ N 次 LLM：门房共享分类器一次出两域结论（已落地）；策略官
  触发条件严格圈定（§3.1）+ 许可单缓存（§3.6）。

## 二、协作流程（一回合时序，插桩点精确到函数）

```
来信/保温/长按触发
  │
  ├─ T1 感知官产感知帧；门房合议（ExpertPanel.reviewIncoming）
  ├─ T2 Director 路由 = REPLY/SMALL_TALK 才继续；NOOP/HANDOFF 出口
  ├─ T3 场景官归属联系人（activeContact）
  ├─ T4 ★策略官 Strategist.permit(...)（§三；触发条件不满足则跳过，
  │      缓存命中则零调用）→ Permit
  ├─ T5 Permit 确定性校验（纯函数）→ 渲染「作战指令段」
  ├─ T6 代言者生成（prompt = 常规段 + 作战指令段 + 禁令段）
  ├─ T7 审查官审查（三查 + 越许可检测 + 红线恒拦）→ 放行/降级起草
  ├─ T8 台账 director_logs + 联络官 assess 动用轻通报
  └─ T9 执行官发送/起草；简报官周报对账
```

- ScreenAdvisor 插桩点：`runAdvisorTurn` 内、组装系统提示词之前调
  `strategist.permit(...)`；`autoForbiddenMerged` 旁挂策略禁令合并。
- 各箭头交接物均为纯数据类（可序列化、可单测、可落台账），无隐式耦合。

## 三、策略官 Strategist 详设（T1 核心）

包位置：`app/src/main/java/com/verlintas/baic2/floatball/experts/strategist/`，
五件套同构（岗位 KDoc 写在包根）：Permit.kt / StrategistRules.kt（纯函数校验）/
StrategistAssets.kt（手段库文案+例句）/ StrategistPrompt.kt / Strategist.kt（门面）。

### 3.1 触发条件与成本纪律

满足其一才调用（否则整段跳过，零成本零时延）：

- 该联系人至少一个维度 = assess 档；
- 或 `stageIntent` 非空（需要本回合正向方针）。

口径：轻 LLM 慢车道（复用 AuxiliaryTasks），≤180 tok、8s 硬超时、
temperature 0.2——与 HandoffGate 同款，增量 <10%。

### 3.2 输入

阶段意图 stageIntent、对方来信段（IncomingCue）、近 2 轮对话缩写、
对方人设三标签+亲疏、四维授权档位表、F1 命中的隐私域（若有）。

### 3.3 输出协议：Permit 许可单（`<tactics>` JSON）

```json
{
  "approach": "value_show|charm|benefit_list|empathy|humor|story|mixed",
  "disclosure": {
    "use": true,
    "domain": "p3",
    "why": "展示实力促进信任",
    "claim": "承接过30+同类项目"
  },
  "lying": { "use": false, "why": "", "claim": "" },
  "promising": {
    "use": true,
    "why": "推进成交",
    "claim": "周末内寄样品",
    "within": true
  },
  "exemplifying": { "use": true, "why": "类比降低理解成本", "claim": "" }
}
```

- `approach`：本回合**重点**正向手段（非唯一许可——手段库段永远全量开放，
  防策略官失误锁死代言者，见 §四）。
- 敏感三维各一个 `{use, why, claim}`；`within=false`（许愿超承受范围）时
  该维强制转「问主人」通道（§六）。
- 解析失败/超时/畸形 → null（走 §3.5 降级）。

### 3.4 确定性校验（StrategistRules，纯函数 JVM 可单测）

1. **档位闸**：never 档维度 `use=true` → 剥除该维（宪法优先于军令）；
2. **claim 词表闸**：promising.claim 命中金额/期限/身份类承诺词（D4 词表）
   且档位=assess → 标记 `needsHuman=true`（转问主人，不发送）；
3. **红线闸**：claim 命中红线死清单词表（§八）→ 整单作废该维并记违规；
4. **approach 归一**：未知值归 mixed。

### 3.5 失败降级（绝不阻塞回合）

策略官任何失败（LLM 超时/无配置/畸形/校验全废）→ 本回合 Permit=null：

- assess 档维度渲染为禁令句（等价 never，现状口径）；
- 正向手段库段照常注入（代言者仍可自然运用正向手段）；
- 台账记 `tactic_permit_skip`。回合链条零中断。

### 3.6 许可单缓存

内存 `MutableMap<contactId, (Permit, createdAt)>`，TTL 90s（D7）：同屏
连发多回合复用同一许可单；TTL 过期或来信内容相似度骤变（复用
PromptDedup 指纹）即失效重算。缓存命中台账记 `tactic_permit_cached`。

## 四、代言者 Responder：作战指令段（StrategistAssets 渲染）

Permit 校验通过后渲染两段拼进系统提示词（规约总纲之后）：

1. **手段库段（永远注入，无需许可）**：正向手段全量开放——人格魅力吸引 /
   价值展示 / 利弊陈述 / 举例类比 / 幽默共情；stageIntent 有值时显式带入
   「本阶段你要推进：{stageIntent}」；正文绝不出现"目标/策略/方针"字样。
2. **作战指令段（有 Permit 才注入）**：「本回合重点用 {approach 文案}」+
   各敏感维处置：「可自然提及 {claim}（理由：{why}）」/「本回合不要提X」/
   「{claim} 超出授权，如对方坚持则表示需确认」。
3. **禁令段**：never 档 + 红线（合并进现有 AUTO_FORBIDDEN_ITEMS 渲染路径）。

## 五、审查官 Gatekeeper：按档执法（越许可检测）

`deterministicReview` 增加策略上下文（Permit + 档位表）：

| 检测                                                     | 处置                        |
| -------------------------------------------------------- | --------------------------- |
| 承诺语词表命中 & promising 未批（use=false 或无 Permit） | 拦截→降级起草（不丢稿）     |
| 承诺语命中 & 已批 & within=true                          | 放行                        |
| 敏感隐私语命中 & disclosure 未批                         | 拦截→降级起草               |
| 红线死清单词表（§八）                                    | **任何档位恒拦** → 降级起草 |
| 其余三查（红线黑名单/超长/重复）                         | 现状不变                    |

批准偏置不变：词表漏判不新增拦截面，宁可放行不误伤（与 M1 口径一致）。

## 六、执行官/联络官：留痕、通报、问主人

- 台账：`director_logs` 新 reason 键——`tactic_permit_ok`（附 approach）、
  `tactic_permit_cached`、`tactic_permit_skip`、`tactic_veto_<维>`（审查拦截）、
  `tactic_human_needed`（许愿超范围）。
- 轻通报：assess 档维度 `use=true` 实际生效后，联络官 postLight（F1 静音
  渠道复用）「已按策略动用{撒谎|许愿|隐私披露}：{why}」，30min 节流复用。
- 问主人：`needsHuman=true` → E1 通报链挂 await-human（复用挂起机制），
  主人分屏发言解除；该维本回合不发送。
- 周报：BriefCompiler 增「策略动用统计」（四维×档位×次数+最近 3 条 claim）。

## 八、红线死清单（绝对禁区，free 档也不行）

金钱交易事实性欺骗（谎称已付款/假凭证）｜法律后果承诺（代签/担保）｜
医疗人身安全谎言｜冒充真实机构/职务背书｜泄露第三方隐私。
→ 确定性词表进 Gatekeeper 恒拦段 + 泄露锁单测锁死（D3 待用户增删）。

## 十一、我的增强建议（超出指令的三点）

1. **approach 是重点不是许可**：正向手段永远全量开放（§四.1），策略官只定
   本回合重点——避免 LLM 一次误判把代言者锁死成只会一招；
2. **保温回合预生成**：M2-b 闹钟检点时（慢车道、用户无等待）提前算好
   许可单入缓存，保温发言零时延；
3. **策略动用回归集**：eval 模块加 mock 供应商断言集（给定来信+档位→
   期望 Permit 形态），词表/prompt 改动可回归验证，防裁量漂移。
