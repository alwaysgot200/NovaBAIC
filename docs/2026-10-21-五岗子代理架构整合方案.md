# 五岗子代理架构整合方案（岗位收敛与协作宪法）

v1（2026-10-21）。按用户指令：子代理**最少化、责任范围明确化、既有功能
不得减少**；本方案是全系统子代理架构的唯一归属口径，取代此前所有
「岗位表述」（2026-10-20 组织模式文档的合议团口径、T1 方案的十岗表、
历次会话中的临时称谓）。落地方式=门面+归属声明，**零包重排零行为变化**。

---

## 一、整合动机与原则

1. **子代理 = 有独立判断职责的决策实体**，不是「有头衔的模块」。是否烧
   LLM 不是划分标准，业务职责才是——感知/执行是器官，不占岗位。
2. **一个岗位管一段不可再合并的职责**：合并会让单次 prompt 职责过载、
   时序错位（门房读信瞬间判 vs 军师等路由后定方针）。
3. **成本纪律不变**：每回合典型 2 次 LLM（代言者+审查官），最多 4 次；
   慢车道（档案官）与回合链无关。

## 二、五岗制总表（唯一口径）

| 岗位 | 唯一职责（一句话） | 快车道（每回合） | 慢车道（低频） | 门面实体 |
| --- | --- | --- | --- | --- |
| **哨官 Sentry** | **理解对方**：来信在干什么 | ExpertPanel 三域合议（接管H/隐私/达成G，词表优先零LLM）+ SceneGate 场景兜底（UNCERTAIN 才 LLM） | — | ExpertPanel（已落地，F1） |
| **军师 Strategist** | **决定打法**：本回合怎么打 | DirectorRoutes 路由（纯函数）+ **T1 许可单 LLM**（条件圈定+90s缓存）+ TopicEngine/WarmChatPrompt 话题（本地算法） | TopicPlanner 周规划 + ActionPlanner 行动建议 | experts/strategist/Strategist.kt（T1 新建） |
| **代言者 Responder** | **产出回复**：按指令写出可发的话 | AdvisorResponder 流式生成 + ChatBriefBuilder 素材组装 + SendableDraftExtractor 纯回复抽取 | — | AdvisorResponder（现状即是） |
| **审查官 Gatekeeper** | **风控放行**：稿子能不能发 | 确定性三查 + 轻LLM审 + **T1 越许可检测** + 红线死清单恒拦 | — | Gatekeeper（现状即是） |

| 器官 | 实体 | 职责 |
| --- | --- | --- |
| 感知器官 | ScreenPerceiver / FrameDiffEngine / FrameQuality | 产感知帧（a11y→截图→投影阶梯降级，技术策略非业务判断） |

**净效果**：岗位从「历史各种临时称谓 ~12 个」收敛为 **5 岗 + 2 器官**；
LLM 调用点数量不变（9 处）；每回合预算不变；零功能删减。

## 四、协作流程（一回合 + 慢车道）

```
【回合链】
感知器官 → 感知帧
  → 哨官 → IncomingReview（三域+场景+归属：对方是谁、说了什么、要不要紧）
  → 军师 → Route（回不回）+ Permit 许可单（怎么打：approach+敏感手段授权）
  → 代言者 → Draft（按军师指令 + 哨官人设素材写稿）
  → 审查官 → Review（放行/降级起草/问主人：按许可单验稿）
  → 执行器官 → 发送/通报/台账
【后台慢车道，与回合解耦】
  档案官：萃取画像/摘要/事实三源捕获（回合后）；
          FactScheduler 每日 08:00 检点日期型事实 → 参谋建议（仅主人可见）；
          TopicPlanner 周规划 → 军师话题弹药；BriefCompiler 周报对账。
```

**交接物全部结构化可序列化**（IncomingReview/Permit/Draft/Review/事实行），
无隐式耦合；「模型只能提案、代码执法」的既有铁律不变。

## 五、落地方式（零风险）

1. **零包重排**：既有类一个不搬家（合并上游冲突面最小）；岗位归属以
   **包根 KDoc 岗位声明 + 门面聚合**确立。
2. 哨官：ExpertPanel 已是门面（F1 落地），补 SceneGate 归属 KDoc。
3. 军师：T1 实施时新建 `experts/strategist/Strategist.kt` 门面（聚合路由
   调用+许可单），`docs/2026-10-21-聊天策略裁量层方案.md`（v2）按本方案
   口径修正岗位名——策略官=军师的快车道 LLM 职责。
4. 档案官：F2 实施时新建 `experts/facts/` 包（原方案即此位置，天然归位）。
5. 代言者/审查官：现状即是门面，不动。
6. 组织模式文档（2026-10-20）的「五件套+合议团」铁律**继续有效**——
   五件套是子代理的内部结构，五岗是子代理的业务归属，两者是「房间的
   家具」与「楼层的户型」的关系。

## 六、验收标准

- 本方案本身：纯文档，无代码变化（编译/单测/冒烟自然全绿）。
- 后续 T1/F2 落地时按本表归属落位，新代码的门面与 KDoc 必须声明岗位。
- 每回合 LLM 预算审计口径：典型 2 次、上限 4 次（哨官词表短路、军师
  条件+缓存短路）——回归测试与台账断言以此为锁。
