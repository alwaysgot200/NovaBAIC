## 1. 目标

1. App「AI 服务」页只做两件事：**从服务端模型目录中选定一个模型**、**编辑该模型的通用参数**；不再有「添加服务/删除服务/多个 Agent」。
2. 服务端随时增/下线模型；App 自动看到可用模型、展示名、积分倍率、token 能力（max 模式/精细度）。
3. 新模型接入流程固定：管理端配置上游供应商（key/baseUrl/上游模型）→ 配置下游模型（展示名/倍率/appVisible/maxTokens）→ LiteLLM 自动同步 → App 自动出现。
4. App 所有「token 用量」展示统一改成「积分消耗」：主页对话、分屏会话、浮球设置用量统计。
5. 后台「我的订单」新增「AI 积分消耗统计」页：时间、模型、消耗积分、内容前 30 字。

## 2. 方案 A：AI 服务模型化

### 2.1 服务端数据结构

`llm_model` 增加两列（迁移 + seed 双写）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `max_tokens` | `Int?` | 该模型允许的最大输出 tokens；App「Max 模式」直接采用 |
| `supports_reasoning` | `Boolean default false` | 是否支持思考模式（替代按模型名猜测） |

`appVisible` 已存在。管理端模型抽屉补三项：展示名（`remark` 沿用或新增 `display_name`，见 §2.6）、积分倍率（coefficientMilli/1000）、`maxTokens`、`supportsReasoning`、`appVisible`。

`GET /api/v1/point-card/gateway/config` 每项扩展为：

```json
{
  "key": "mimo-2.6-flash",
  "displayName": "MiMo 2.6 Flash",
  "coefficientMilli": 100,
  "coefficientLabel": "0.1x",
  "maxTokens": 8192,
  "supportsReasoning": false,
  "modes": [
    { "key": "max", "label": "Max", "maxTokens": 8192 },
    { "key": "standard", "label": "标准", "maxTokens": 4096 },
    { "key": "economy", "label": "精省", "maxTokens": 1024 }
  ]
}
```

- `modes` 由服务端按 `maxTokens` 派生（max=上限、standard=上限/2、economy=上限/8，并夹到 512..上限），保证未来模型无需改 App。
- `baseUrl` 仍是统一 `/llm/v1`；**下游 API 地址不按模型拆分**——模型别名（modelKey）即路由，LiteLLM 负责把 `mimo-2.6-flash` 转到供应商上游地址。App 永不接触上游地址。

### 2.2 App 设置页（替换 AgentsPage）

`feature/settings/SettingsPages.kt`：

- 删除「添加服务」按钮、删除按钮、默认圆点、Agent 多卡列表。
- 改为 **模型目录卡片**（数据来自 `AdvisorGateway.config()`）：
  - 卡片主标题：`displayName`；
  - 副标题：`modelKey · 积分倍率 0.1x · 最大输出 8K`；
  - 当前选中模型高亮 + ✓；
  - 点击卡片 = 选中该模型并进入「模型设置」。
- 空态：服务端无可用模型时提示「当前无可用模型，请稍后再试」。
- 未绑卡：仍可浏览模型，但保存时提示先绑定卡密。

`AgentWizardScreen.kt` 改为 **模型设置页**（两步：参数 → 系统提示词）：

- 顶部显示模型名/倍率（只读）；
- 「Max 模式」开关：开 = `maxTokens = mode.max`；关 = 三档精细度单选（精省/标准/深入，按服务端 `modes`）；
- 温度、系统提示词；
- 保存：更新默认 Agent（`model`、`baseUrl`、`maxTokens`、`reasoning`、`temperature`、`systemPrompt`），apiKey 取当前卡密；
- 不再有服务商、Key、地址、模型下拉。

### 2.3 单一当前模型

- 内部仍复用 `Agent` 表，但只保留 1 个默认 Agent（`isDefault=1`）。
- 历史多 Agent：迁移时保留最早/默认一个，其余在设置页不展示（不物理删除，避免聊天记录 agentId 悬空；默认 Agent 被切换时自动更新）。
- 会话仍按 `agentId` 取配置；切换模型后新会话使用新配置，历史会话继续用其绑定 Agent。

### 2.4 未来新增模型（示例 mimo-2.6-flash）

1. 管理端「LLM 供应商」新增 `mimo`：baseUrl、上游 API Key（加密落库）；
2. 「LLM 模型」新增：`modelKey=mimo-2.6-flash`、`upstreamModel=<上游真实名>`、`coefficientMilli=100`（0.1x）、`maxTokens=8192`、`appVisible=true`；
3. 保存即自动同步 LiteLLM（现有 `syncModel`）；
4. App 下次进入 AI 服务页自动出现 `MiMo 2.6 Flash · 0.1x · Max`，无需发版。

### 2.5 下线模型

管理端 `enabled=false` 或 `appVisible=false` → App 目录立即不再出现；已选中的模型若被下线，设置页回退到第一个可用模型并提示。

### 2.6 展示名

`llm_model` 增加 `display_name VarChar(100)`（可空，空则回退 `modelKey`）。管理端可填中文/品牌名；`gateway/config` 返回它。

## 3. 方案 B：积分消耗统一口径

### 3.1 客户端（App）

1. **本地库 v21 → v22**：`messages` 增加 `usagePointsMilli INTEGER`；`ChatMessage` 增加 `usagePointsMilli`，映射/DAO 同步。
2. **积分公式客户端同口径**（新增 `core/model/PointsPricing.kt`）：
   `B毫积分 = (输入×1 + 缓存×0.1 + 输出×3) ÷ 1000`；`D毫积分 = max(100, ceilDiv(B × M, 100000) × 100)`。
3. **归属**：新增 `ModelPricing` 单例（core:model），由 app 在拉取 `gateway/config` 后写入 `modelKey → coefficientMilli`；未命中按 1000（1.0x）。
4. **落库**：
   - 主页对话：`core/engine/AgentLoop.kt` 保存助手消息时同时写 `usagePointsMilli`；
   - 分屏会话：`ScreenAdvisor.kt` 多处构造消息时写 `usagePointsMilli`；
   - `AdvisorPrefs.TokenStats` 扩展 `totalPointsMilli/sessionPointsMilli`，`recordTurnUsage(input, output, modelKey)` 同时累计积分。
5. **展示替换**：
   - `MessageViews.kt`：`积分 1.2`（无积分时回退隐藏，不再显示 ↑/↓）；
   - `TranscriptView.kt`：`积分 1.2`；
   - `FloatSettingsActivity` 用量卡片：`累计消耗 X 积分 · N 轮`、`本次会话 Y 积分`；
   - 字符串资源 zh/en 同步。
6. 上下文占用条（`~3.0K/1.0M`）**保留**——它服务上下文管理，不是费用。

### 3.2 服务端：内容摘要采集

1. App 网关请求（`OpenAiCompatibleProvider`）在 `baseUrl` 含 `/llm/v1` 时增加请求头：
   `x-litellm-spend-logs-metadata: {"preview":"<最后一条用户消息前30字>"}`（JSON 转义）。
2. `litellm-gateway.service.ts#toSpendEntry` 解析 `metadata.spend_logs_metadata`（可能是 JSON 字符串），提取 `preview` 写入 `LlmSpendLogEntry.preview`。
3. 结算链：`settleEntry → PointsLedger.deductForUsage(params.preview)` → `llm_usage_record.content_preview`。
4. `llm_usage_record` 增加 `content_preview VarChar(120)`；迁移文件 + schema。
5. 摘要只存 30 字，不存完整对话；不涉及敏感信息扩展。

### 3.3 服务端：用户自助统计接口

```
GET /api/v1/point-card/my/ai-usage?pageNum=1&pageSize=20
→ { rows: [{ createTime, modelKey, deductPointsMilli(字符串), contentPreview }], total, pageNum, pageSize, pages }
```

- 登录态强制当前 `userId`，不跨租户/跨用户；
- 数据源 `llm_usage_record`，按 `createTime` 倒序；
- 错误码沿用商业化 8xxx 段，无需新增；
- Swagger + ResponseDto + 分页信封；只读不加 Operlog。

### 3.4 后台「AI 积分消耗统计」页

- 新页面 `apps/web/src/views/market/ai-usage/index.vue`：
  - 表格列：时间 / 模型 / 消耗积分 / 内容（前30字，超出省略）；
  - 复用 `useTable` + NDataTable；
  - 顶部展示当前账户积分余额（复用 `/point-card/wallet`）。
- 入口：`我的订单` 页顶部新增按钮「AI 积分消耗统计」跳转 `/market/ai-usage`，并在侧边栏菜单「我的订单」下新增子菜单 `3104 AI 积分消耗`。
- 菜单/权限基线（遵循 §8.1）：
  - 迁移 DML 固定 id `3104` + `3105`（按钮/页面查看权限 `market:usage:list`）；
  - `seed.ts` 快照同步；
  - `verify-integrity` 菜单白名单新增 3104/3105；
  - 产品角色模板/租户套餐 `menu_ids` 追加 3104。
- 前端 API：`service/api/commerce/ai-usage.ts` + `typings/api/commerce.api.d.ts` 新命名空间 `Api.Commerce.AiUsage`。

## 4. 验收（真机 + dev）

1. App AI 服务页无「添加服务/删除/默认圆点」，只有模型卡片；卡片显示名称、倍率、最大输出。
2. 选择 `DeepSeek Pro` 保存后，主页对话与分屏对话底部显示「积分 X」，不再是 ↑/↓ token。
3. 浮球设置用量卡片显示累计/本次积分。
4. 管理端新增 `mimo-2.6-flash`（系数 0.1x）→ App 下拉/卡片立即出现 `0.1x`，并能选中保存；下线后消失。
5. 发一轮对话后 ≤ 2 分钟：后台「我的订单 → AI 积分消耗」出现一行（时间/模型/实际扣点/前30字）。
6. 内容摘要仅 30 字；越权接口只返回本人数据。
7. `pnpm typecheck/lint`、`assembleDebug`、迁移 `verify-integrity` 全绿。
