## 1. 需求 1：身份类型快捷下拉（聊天第一要务）

**现状**：`contact_profiles.identity` 已存在（词表 `StyleVocab.IDENTITIES`：
领导/客户/同事/朋友/家人/暧昧对象/其他），但设置入口藏在「目标」Tab 的
「双方人设与维持度」卡里（芯片行，`AdvisorPersonaCard`），不顺手。

**改动**（零数据迁移）：

1. `ContactDetailScreen` 画像 Tab 顶部（类型/改名之前）新增常驻一行：
   **「身份类型（先定身份，再聊风格）」下拉**（`ExposedDropdownMenuBox`），
   选项 = `StyleVocab.IDENTITIES` 原词，显示当前值，空值显示「待确定」。
2. 选择即落库：`ContactRepository.setStyleTags(contactId, identity, chatStyle, closeness)`
   （只改 identity，其余两值透传不动），与「目标」Tab 的 identity **同一字段同一词表**，
   两处实时同源（`observeProfile` Flow 刷新）。
3. 若存在 AI 待确认身份（`selfFacetPendingJson` 中的 style pending identity），
   下拉行尾显示「AI 建议：xx」小字 + 一键采纳；手动选择优先，采纳即清该 pending。
4. 文案全部进 `strings.xml`（`float_identity_quick_*` 前缀）。

## 2. 需求 2：对方 / 我方分区明确化

**现状**：`AdvisorPersonaCard`（`GoalTab` 内挂载）一张大卡里混排了「对方标签 /
我方侧面 / 维持度 / 隐私策略 / 聊天手段 / 阶段意图 / 合并档案」，虽然有
`SectionLabel`，但归属感弱，用户分不清在设置谁。

**改动**（纯 UI 重组，数据零变动）：把该卡拆成三个**视觉独立、归属写在标题里**的
分区（同卡内三段，段间分隔 + 各自归属色带/标题副题）：

| 分区标题（文案可再调） | 归属副题 | 内容 |
| --- | --- | --- |
| **TA 的人设（对方是谁）** | 「以下设置的都是对方」 | identity / chatStyle / closeness 三标签 + 待确认建议 |
| **我的侧面（我在我与 TA 的关系里是谁）** | 「以下设置的都是你自己」 | selfFacet 标签 + pending 核阅 + 全局我方人设入口 |
| **关系维持与聊天策略** | 「这是你和 TA 的相处方式」 | 维持度三档 / 隐私策略 / 聊天手段三维 / 阶段意图 / 单聊群聊 / 合并档案 |

实现要点：

- 新建 `AdvisorPersonaCard.kt` 内三个 `PersonaZone` 子区块（同文件重构，不新开大文件），
  分区标题用 `titleSmall` 加粗 + 归属副题 `bodySmall`，对方区/我方区分别用
  `primaryContainer` / `tertiaryContainer` 浅色底衬（走 `Baic2Theme` token，不硬编码色）。
- 「目标」Tab 顶部的业务目标一行补归属说明文案：「本关系要达成的目标（我方意图）」。
- 字段语义、写库路径全部不变；纯展示重组 + 文案，回归面小。

## 3. 需求 3：「联系方式」Tab（1:N）+ 聊天自动沉淀

### 3.1 数据（advisor.db v15 → v16）

新表 `contact_infos`（一个联系人 N 条）：

```sql
CREATE TABLE IF NOT EXISTS `contact_infos` (
    `id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    `contactId` INTEGER NOT NULL,
    `kind` TEXT NOT NULL,          -- phone/email/address/id_doc/im_account/other
    `label` TEXT NOT NULL DEFAULT '',  -- 自定义说明：单位座机/老家地址/身份证…
    `value` TEXT NOT NULL,
    `note` TEXT NOT NULL DEFAULT '',
    `source` TEXT NOT NULL DEFAULT 'user',  -- user / llm
    `confirmed` INTEGER NOT NULL DEFAULT 0, -- llm 草稿必须人工确认
    `evidence` TEXT,               -- 萃取依据原文短句
    `createdAt` INTEGER NOT NULL,
    `updatedAt` INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS `index_contact_infos_contactId` ON `contact_infos` (`contactId`);
CREATE UNIQUE INDEX IF NOT EXISTS `index_contact_infos_contactId_kind_value`
    ON `contact_infos` (`contactId`, `kind`, `value`);
```

- `MIGRATION_15_16`：建表 IF NOT EXISTS + 索引，不搬不删既有数据（沿用
  `AdvisorDatabase` 既有迁移纪律，DDL 与实体逐字对齐，Room 2.8 开库校验）。
- 复合唯一键 `(contactId, kind, value)` 防同一号码重复入档；同 kind 多值天然支持。

### 3.2 聊天自动沉淀（重点）

1. `PersonaExtractor` 输出协议扩展一段：
   `"contactInfos":[{"kind":"phone","value":"138…","label":"微信里留的手机号","evidence":"原文短句"}]`
   （字段缺省容忍，`ignoreUnknownKeys` 已就绪）；解析侧做正则归一校验
   （手机号 `1[3-9]\d{9}`、邮箱、身份证宽松校验），不合法直接丢弃，单次 ≤3 条。
2. 落库即 **AI 草稿**（`source=llm, confirmed=0`，唯一键命中则刷新 evidence/updatedAt），
   与画像字段草稿同一纪律：**模型只提案，人确认才生效**。
3. 用户在「联系方式」Tab **确认**后走 `ProfileMemorySync` 双写上游记忆
   （`NoteKind.PROFILE`：「张三的电话：138xxxx」，entities=[主名+别名]），
   手动新增/修改同样双写——满足「自动更新记忆和学习沉淀」。

### 3.3 UI：第 5 个平级 Tab「联系方式」

- `ContactDetailScreen` TabRow 追加「联系方式」（TAB_INDEX_CONTACTS=4），
  内容按 kind 分组卡片（电话 / 邮箱 / 地点 / 证件 / 其他 IM / 其他），每条卡片：
  值 + label + 备注 + 来源徽章（「AI 待确认」→ 确认/丢弃按钮；「已确认」）。
- 顶部「+ 添加」：kind 下拉 + 标签 + 值 + 备注，保存即 source=user、confirmed=1。
- 空态引导文案：「聊天中提到的电话、地址会自动沉淀到这里，确认后长期记忆。」
- 遵守 §4.4 全屏一致性（`AdvisorPage`/`PageScaffold` 既有骨架内，不自绘顶栏）。

## 4. 需求 4：画像属性扩充（自动学习优先）

新增组「生活品味」（owner=their，默认可萃取）：

| key | 标签 | 类型 | 说明 |
| --- | --- | --- | --- |

| `favPlaces` | 常去地点 | tags | 城市角落/餐厅/球场… |

### 5.3 聊天中参考使用（两条链路同享）

现状：`ChatBriefBuilder.build` 已按「对方最新发言 + 目标关键词」检索 Top-3 话术
注入提示词段【参考话术】（`ScreenAdvisor` 提示词组装，参谋会话与自动聊天会话共用）。

增强——**按身份类型定向召回**：

1. `PlaybookRetriever` 新增 `categoriesForIdentity(identity)` 映射：
   领导→职场+官场；客户→销售+职场；同事→职场；朋友→朋友+娱乐场；
   家人→亲人+通用哲理；暧昧对象→情人+娱乐场；其他/空→全类。
2. `ChatBriefBuilder` 召回改为：**先在身份类目内取 Top-3，不足再全类补足**
   （话术段永不空缺优先级下降为「有则给、无则省」，维持现状语义）。
   identity 未定时走全类，行为与今一致。
3. 效果：与领导聊天自动偏向职场/官场话术，与暧昧对象聊天自动偏向情话，
   与客户聊天自动偏向销售话术——参谋会话与自动聊天会话同步生效。

**可选阶段 B（默认不做，待批准后决定）**：分屏面板加「参考话术」折叠条，
展示本回合进入提示词的 Top-3 话术（`FloatUi`/`TranscriptView` 接线），让「参考」可见。

## 8. 风险与边界

- **迁移安全**：v16 只建新表，不碰既有表（遵守「迁移必须保留历史数据」铁律）；
  升级后旧数据行为逐字不变。
- **萃取成本**：新字段会进萃取目录，单次萃取输出条数已有 `MAX_DRAFTS=5` 封顶，
  无额外 LLM 调用次数；联系方式萃取同一次调用产出，不加调用。
- **隐私**：电话/证件属敏感事实——只落本地 advisor.db 与用户确认后的本地记忆，
  不上传、不进遥测；萃取草稿未确认前不进任何提示词（既有纪律）。
- **话术重播种**：SEED_VERSION 升级会重建内置话术（用户自定义保留），
  用户若改过内置条目会丢失（当前 UI 不支持改内置，实际风险≈0）。
- **不做**：不加新 Gradle 模块、不改上游文件、不动 `core:*`；可选阶段 B 默认不做。
