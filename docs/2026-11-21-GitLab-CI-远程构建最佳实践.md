# GitLab CI 远程构建最佳实践（NovaBAIC @ 192.168.1.100）

> 2026-11-21 定版。本文是「本机改代码 → 一条命令发版 → 1.100 自动构建/测试 → 本机下载并分析产物」这条链路的
> 唯一操作手册，同时沉淀搭建过程中踩过的全部坑。配置事实以 `.gitlab-ci.yml`、`build-client.ps1`、
> `tools/ci-*.sh` 为准，本文与代码冲突时以代码为准并同步回本文。

---

## 1. 链路总览

```
本机 (Windows)                         1.100 (Ubuntu, Docker Runner "moni-100")
┌────────────────────────┐             ┌────────────────────────────────────────────┐
│ 修改代码               │             │ 作业容器 baic2-android-build:1             │
│ build-client.ps1 ci    │  git push   │   verify: tag 校验 + license/strings/schema │
│  ├─ 提交(可选)         │ ──────────► │           + 单测 + lintRelease              │
│  ├─ 推 laocanmou       │  tag vX.Y.Z │   build : tag 派生版本 + 签名 + apksigner    │
│  ├─ 打/推 tag          │ ──────────► │           校验 + 上传 APK/mapping            │
│  ├─ 轮询 pipeline      │             │   device: 连宿主 sidecar 模拟器, 装 debug 包 │
│  ├─ 下载产物           │ ◄────────── │           + connectedAndroidTest + 冒烟截图  │
│  └─ 装 1.100 模拟器     │  artifacts  └────────────────────────────────────────────┘
│ releases/vX.Y.Z/       │                     │ adb (docker 桥网关:5555)
│ ci-login 免登录调试     │                     ▼
└────────────────────────┘             ┌────────────────────────────────────────────┐
         │ SSH -L 15555                 │ 宿主常驻模拟器 sidecar (KVM + ARM 翻译)      │
         └─────────────────────────────►│ qemu-system-x86_64 -port 5554              │
                                        │ socat 5580 -> 127.0.0.1:5555               │
                                        └────────────────────────────────────────────┘
```

关键事实（2026-11-21 实测）：

| 项 | 值 |
| --- | --- |
| GitLab | `http://192.168.1.101`，**15.5.4 CE**（`GET /api/v4/metadata` 实测，未升级），项目 `wuruixi/NovaBAIC` = **project id 69** |
| Runner | Docker executor，tag `moni-100`，镜像 `baic2-android-build:1` |
| 分支 / 标签 | `laocanmou`；`vX.Y.Z`（必须指向分支 tip） |
| 流水线 | verify → build → device；冷缓存约 25~30 分钟，热缓存约 10 分钟 |
| 实测（#2212） | verify 00:48 / build 07:07 / device 01:39；APK 41.5 MB，versionCode 10001 |
| 产物保留 | build 30 天，verify/device 7~14 天；本机 `releases/` 永久留档 |

## 2. 日常操作（唯一入口：`build-client.ps1`）

### 2.1 交互菜单

```powershell
.\build-client.ps1          # 主菜单选 7) 远程发布 / CI
```

| 菜单项 | 等价命令 | 作用 |
| --- | --- | --- |
| 1 发版 | `ci -Commit` | 提交全部改动 → 推送 `laocanmou` → 自动版本号打 tag → 等 CI → 下载到 `releases/<tag>` |
| 2 状态 | `ci-status` | 最近流水线 + 作业耗时；失败作业自动打印日志尾部 |
| 3 下载 | `ci-download` | 下载最近一次成功流水线的产物 |
| 4 重打 | `ci-retag -Version vX.Y.Z` | 删远端 tag → 重打当前 HEAD → 重推 → 重跑 |
| 5 装模拟器 | `ci-install` | SSH 隧道连 1.100 模拟器，安装 `releases/` 最新签名包 |
| 6 免登录 | `ci-login` | 本地 `assembleDebug` → 装进 1.100 模拟器 → `dev/dev-login.ps1` 注入测试账号 |

### 2.2 非交互示例

```powershell
.\build-client.ps1 ci -Version v1.0.2 -Commit -Install   # 指定版本, 提交全部改动, 通过后装机
.\build-client.ps1 ci -Commit -ReleaseMessage "feat: 新增 RPA 动作"   # 自定义提交说明
.\build-client.ps1 ci-status
.\build-client.ps1 ci-download
.\build-client.ps1 ci-retag -Version v1.0.2
.\build-client.ps1 ci-login
```

### 2.3 产物落点

```
releases/v1.0.2/
  NovaBAIC-v1.0.2.apk          # 平铺的签名包（已 SHA256 校验）
  mapping.txt                  # 混淆映射（崩溃符号化用）
  artifacts-build/             # build 作业原始产物
  artifacts-device/ci-out/     # 冒烟截图、instrumented 测试报告
  artifacts-verify/            # lint 报告、单测报告
```

`releases/` 已被 `.gitignore` 整目录忽略，不进版本库。

## 3. 踩坑清单（按现象 → 根因 → 对策）

### 3.1 触发与版本

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 1 | tag 推上去 CI 拒绝 | GitLab 会用 `CI_COMMIT_SHA` 与 `laocanmou` tip 对比 | 必须先推分支再打 tag；`ci`/`ci-retag` 已内置该顺序 |
| 2 | 重推同名 tag 没触发新流水线/抓到旧流水线 | GitLab 对同 ref 保留历史流水线 | 重打用 `ci-retag`（删远端 tag → 重打 → 重推），并按「推送前已存在的 pipeline id」排除旧记录 |
| 3 | 版本号撞车 | 只按本地 tag 计算 | 发版前 `git fetch gitlab --tags`，取最大 `vX.Y.Z` 补丁号 +1 |
| 4 | versionCode 回退导致覆盖安装失败 | 公式 `MAJOR*10000+MINOR*100+PATCH` | CI 强制 MINOR/PATCH ≤ 99；本地不要手改 `build.gradle.kts` 版本 |

### 3.2 Runner 与镜像

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 5 | 每个作业都重下 Gradle 依赖，verify 32 分钟 | 作业容器是一次性的，`~/.gradle` 每次清空 | Runner 把宿主 `/cache` 挂进容器；CI 设 `GRADLE_USER_HOME=/cache/gradle`（热缓存 verify 约 40 秒） |
| 6 | SDK 预检报目录不可写 / 缺 build-tools | 镜像里 SDK 权限与 AGP 版本探测不匹配 | 镜像构建期预装 platform 35/36 与 build-tools 36.0.0；CI 只读使用 |
| 7 | `git submodule` 拉取 TLS 中断（GnuTLS -110） | 1.100 到 github.com 的链路不稳，且 `vendor/assists` 不是 Gradle 模块 | `GIT_SUBMODULE_STRATEGY: none` |
| 8 | 镜像/资产把根分区撑爆 | Docker 镜像默认在 ext4 `/`，SDK/AVD/APK 很大 | 镜像留 `/`（overlay 性能好），SDK/AVD/缓存/APK 全部放 `/d`（大分区），容器只读挂载或宿主侧执行 |

### 3.3 产物与日志

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 9 | 上传 artifacts 报 413 | GitLab 单作业 artifacts 上限约 100 MB，debug APK 有 145 MB | build 只归档 release APK + sha256 + mapping（压缩后约 28 MB）；debug 由 device 作业自己构建，不重复归档 |
| 10 | 失败后什么现场都没有 | Docker Runner 作业容器结束即销毁 | 测试报告与截图用 `when: always` 上传；本机 `ci-status` 直接拉 job trace |
| 11 | `.gitlab-ci.yml` 报 YAML 语法错 | 以 `"` 开头的命令被 YAML 当成引号串 | 整条命令用单引号包裹，如 `- '"$ADB" connect "$TARGET"'` |

### 3.4 设备线（模拟器）

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 12 | 作业容器连不上模拟器 | 模拟器跑在宿主 sidecar，容器里没有 KVM/图形栈；`127.0.0.1:5555` 在容器里指向自己 | 用 docker 桥默认网关：`GW=$(ip route | awk '/default/ {print $3}')`，连 `$GW:5555` |
| 13 | 模拟器 adb 端口不可用 | emulator 的 console/adb 端口必须是偶数（5554→5555），且默认只绑 loopback | `-port 5554` 启动；宿主 `socat TCP-LISTEN:5580,fork TCP:127.0.0.1:5555` 暴露给桥 |
| 14 | 本机 `adb connect 192.168.1.100:5555` 超时 | 1.100 防火墙不放行 5555，且服务只绑回环 | 本机走 SSH 本地转发：`ssh -N -L 15555:127.0.0.1:5555 moni-cibuild`，再 `adb connect 127.0.0.1:15555`（`ci-install` 已内置） |
| 15 | assumeTrue 的前置不满足被判 failure | AGP 把 `AssumptionViolatedException` 写成 failure | `tools/ci-check-androidtest.sh` 解析 XML 把前置不满足还原为 SKIP，只有真实断言失败才失败 |
| 16 | ARM 商业 APK 装不上 | 模拟器是 x86_64 | 使用带 ARM 翻译的 Google Emulator 镜像；本项目实测微信 8.0.79 / 淘宝 10.69.10 / 闲鱼 7.29.20 / 拼多多 8.32.0(64 位) 可安装并运行（32 位 only 的包会失败） |

### 3.5 本机脚本（PowerShell 5.1）

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 17 | `Invoke-WebRequest` 走 IE 引擎报错/极慢 | PS 5.1 默认 IE 解析 | 一律 `-UseBasicParsing`；文件哈希用 `Get-FileHash` |
| 18 | 函数返回值被 git 输出污染 | 函数里 `& git ...` 的 stdout 会混进返回值 | 用 `Invoke-Git` 把 git 输出 `| Write-Host`，只返回 bool |
| 19 | 脚本莫名报错 | `$args` / `$pid` 是 PowerShell 保留变量 | 参数用 `$sshArgs`、进程 id 用 `$proc.Id` |
| 20 | 等待隧道时脚本永久挂起 | ssh 弹密码提示 / 端口占用静默失败 | `ssh -N -o BatchMode=yes -o ExitOnForwardFailure=yes`，轮询 60 秒超时并 `Stop-Process` 收尾 |

### 3.6 安装与免登录

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 21 | 覆盖安装报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | debug 包与 release 包签名不同 | 先 `adb uninstall com.verlintas.baic2` 再装；`Install-ReleaseApk` 与 `ci-login` 已自动重试一次 |
| 22 | 注入 debugToken 后仍是登录页 | release 包忽略 debugToken（`TEST_LOGIN_ENABLED` 只看是否 https） | 免登录只能用 debug 构建：`ci-login` 先本地 `assembleDebug` 再走 `dev/dev-login.ps1` |
| 23 | 免登录脚本拒绝执行 | 硬校验 origin 必须是 `http://192.168.1.27` | 保持 `server-config.properties` 的 `server.origin.test` 指向测试服；生产地址一律拒绝 |

### 3.7 安全

| # | 事项 | 做法 |
| --- | --- | --- |
| 24 | 签名密钥 | 不进 GitLab CI 变量；作业里用 `CI_JOB_TOKEN` 稀疏克隆私有 Secrets 仓（`ci/baic2-release.env`），构建后立即删除临时文件 |
| 25 | GitLab PAT | 固定一枚 `name=trae-baic2-ci, scope=api, 永不过期`，只存本机 `d:\work\Secrets\ci\gitlab-pat.env`（已入 Secrets 仓）；工程仓库零密钥。**禁止再随手创建临时 PAT**，轮换时撤销旧的并同步此文件 |
| 26 | GitLab 15.5.4 的 PAT API | `POST /user/personal_access_tokens` → 404，`/users/:id/...` → 403；只能走网页会话：`POST /-/profile/personal_access_tokens`（注意是 `/profile` 前缀；页面是 Vue，无 `authenticity_token` 隐藏域，须从 `<meta name="csrf-token">` 取值，同时带 `X-CSRF-Token` 头与 body `authenticity_token`；`personal_access_token[expires_at]` 留空 = never expires，实例策略允许）。撤销用 `DELETE /personal_access_tokens/:id`（204，仅置 revoked，行保留至到期日） |

## 4. 排障手册

```powershell
# 1) 看最近流水线与作业耗时, 失败作业自动带日志尾部
.\build-client.ps1 ci-status

# 2) 单独看某个 job 的完整日志 (网页)
#    http://192.168.1.101/wuruixi/NovaBAIC/-/jobs/<job_id>/raw

# 3) 重新下载产物 (不重跑 CI)
.\build-client.ps1 ci-download

# 4) 环境性失败 / tag 打错提交: 重打当前 HEAD 并重跑
.\build-client.ps1 ci-retag -Version v1.0.2

# 5) 本机验证远端模拟器
ssh -N -L 15555:127.0.0.1:5555 moni-cibuild     # 前台观察连接
adb connect 127.0.0.1:15555
adb -s 127.0.0.1:15555 shell getprop sys.boot_completed

# 6) 1.100 上的现场
ssh moni-cibuild "ls -lt /d/ci/logs | head; tail -100 /d/ci/logs/<最新日志>"
```

判断口径：

- **verify 失败**：先看 license / strings 同步 / tool schema 三检查，再看单测与 lint 报告（`artifacts-verify/`）。
- **build 失败**：看 `version.env` 派生值、Secrets 克隆、签名校验（`apksigner verify`）、`aapt2 dump badging` 与 tag 一致性。
- **device 失败**：看模拟器是否 `sys.boot_completed=1`、商业 APK 是否还在、instrumented 报告与 `ci-out/` 截图。

## 5. 红线

1. 发布只能由用户明确指令触发：`ci` 会推 tag 并触发正式构建，等同于发版。
2. 不把任何密钥写进仓库、CI 变量或文档；PAT 只在本机 Secrets 仓。
3. `releases/`、`tests/tempImg/`、`logs/` 不入库；临时脚本用完即删（本机与 1.100 都是）。
4. 模拟器 sidecar 与 socat 是 CI 的常驻基础设施，不要随手 kill；临时调试完的进程自己收尾。
5. 远端调试只允许测试环境（`http://192.168.1.27`），发现指向生产立即停止并 `dev-login.ps1 -Reset`。
