## 0. 需求（用户原话整理）

1. 问：以微信为例，如何操作绑定与某人的对话，让系统长期获得聊天历史、沉淀画像？
   —— **现状已支持，无需开发**，操作说明见本文 §1。
2. 分屏浮窗标题「老参谋」右侧增加「方向」：单击弹出下拉项（AI 根据上下文
   提取的简明即时方向），也可自行输入；它是**单次聊天的即时目标**，区别于
   联系人档案里的长期业务目标。
3. 分屏小窗口上部收窄、紧凑化：「老参谋」「关闭」「方向」与拖动分隔标记
   放同一行；并为后续「自动」（AI 自动聊天）预留位置。
4. AI 回复内容旁边要有复制图标，方便复制。

## 1. 问题①答复：联系人绑定与画像沉淀的现行操作

**绑定是自动的，不需要手工建档。** 首次在某人聊天页发起参谋时，系统按
「IM 包名 + 聊天页标题（微信顶部昵称/备注名）」懒创建联系人 Stub 档案，
并自动建立该联系人的专属老参谋会话（实现：
[AdvisorContactDirectory.kt](../app/src/main/java/com/verlintas/baic2/floatball/advisor/AdvisorContactDirectory.kt)
的懒建 L3 路径 → `ContactRepository.resolve(createStub=true)`）。

以微信为例的操作序列：

1. **前置权限**（一次性）：悬浮窗权限；建议开启无障碍（识别标题与正文
   更快、免每次投影授权）；模型在主界面「管理平台」配好。
2. 打开微信，进入**与某人的聊天页**（顶部标题即对方名称）。
3. 发起一次参谋：**长按悬浮球**（单次参谋）；或单击球 → 扇形菜单「问答」。
   - 系统优先读无障碍窗口标题；无无障碍时走 OCR 标题带兜底识别。
   - 默认还会**自动上滑拼接 2 屏**历史（设置项「单次参谋上滑屏数」0~3），
     首次绑定即可补采近期聊天。
4. 分屏面板出现后，看标题下方状态条：
   - 显示「当前联系人：张三 ▾」= **已绑定**；
   - 显示「未绑定联系人 ▸ 点此管理画像」= 识别失败（桌面/系统壳/重名模糊），
     回落到的是全体共用的共享会话。
5. **点状态条**进画像管理页（[AdvisorProfileActivity.kt](../app/src/main/java/com/verlintas/baic2/floatball/AdvisorProfileActivity.kt)）：
   - 改主显示名（旧名自动留别名，改名不丢历史）、填**长期业务目标**
     （如「三个月内拿下年度框架订单」）、选语言风格；
   - 「绑定当前会话」可把共享会话里已聊的内容**手工改绑**到该联系人；
   - 重名/疑似同一人可用「合并」（30 天内可撤销）；
   - AI 萃取的画像字段草稿在此页 ✓/✕ 确认，确认后才进提示词。
6. 以后每次在该聊天页参谋（长按单次 / 双击连续模式）都自动进其专属会话，
   状态条持续显示对方名字。

**长期沉淀是怎么发生的（全部本地，无云端）：**

| 沉淀物 | 触发 | 存储 |
| --- | --- | --- |
| 聊天原文（每屏【屏幕内容】+【参谋】回复） | 每次参谋 | 上游会话库，该联系人专属会话 |
| 滚动摘要（≤150 字，带「截至 MM-dd 阶段=X」） | 每 6 个屏幕回合后台压缩 1 次 | advisor.db `session_bindings.digest` |
| 对方画像字段草稿 | 每 5 个屏幕回合后台萃取 1 次 | advisor.db `persona_fields`，画像页确认 |
| 承诺/约见/成交要件 | 按联系人实体直取记忆，只读召回 | 上游 Memory |

**必须向用户说明的边界**：系统不能读取微信数据库，只能获得「你实际发起
参谋时屏幕上可见的内容」（含自动上滑拼接的最多 3 屏）。更老的历史需在
微信里手动上滑定位后再发起参谋补采；连续模式（双击）下停留在聊天页期间
的新消息会被自动差分捕获。

## 2. 问题②：即时「方向」设计

### 2.1 定位：与长期目标分层

| 维度 | 长期目标（已有） | 即时方向（本次新增） |
| --- | --- | --- |
| 粒度 | 一段关系/一单生意 | 这一次聊天、当下几轮 |
| 入口 | 画像管理页文本框 | 分屏顶栏「方向 ▾」chip |
| 示例 | 「推动年度框架签约」 | 「先问出预算区间」「安抚发货投诉」「约下次电话时间」 |
| 生命周期 | 联系人档案长期保存 | 随会话/联系人切换；默认仅服务存活期内保留（见 §6 决策点 B） |
| 提示词 | `【本次聊天的业务目标】`（ChatBriefBuilder） | `【本次参谋的即时方向】`（本方案新增，优先级高于长期目标） |

### 2.2 交互

- 顶栏「方向 ▾」文字 chip：未设置时显示浅色「方向 ▾」；已设置时显示
  「方向：先问出预算 ▾」（单行省略，最长约 10 个汉字宽）。
- 单击弹出浮层菜单（不抢焦点的 PopupWindow，点外部消失）：
  1. **AI 建议区**：≤5 条、每条 ≤12 字。首次点开时按需现场生成
     （生成中显示「AI 拟定中…」行），素材 = 当前屏正文 + 该联系人长期
     目标 + 滚动摘要；同一会话回合内缓存，下一屏幕回合后失效重拟。
     生成失败不阻断：菜单退化为静态兜底项（摸清诉求 / 推进报价 /
     化解顾虑 / 促成下次行动 / 维持关系）。
  2. **「✍ 自定义…」**：弹带输入框的小浮层（复用现有
     `setSplitWindowFocus` overlay 焦点切换机制，键盘避让不新做）。
  3. 已设置方向时底部多一行「✕ 清除方向」。
- 方向**只影响之后的参谋回合**，不改写已生成的回复；切换到别的聊天页
  （activeContact/会话变化）自动切到对应方向，互不串。

### 2.3 AI 拟定（复用，不手搓 HTTP）

- 走 `AuxiliaryTasks.complete(config, systemPrompt, userPrompt, maxTokens≈120)`，
  与滚动摘要同一通道（[ScreenAdvisor.maybeRefreshDigest](../app/src/main/java/com/verlintas/baic2/floatball/ScreenAdvisor.kt) 已有用法）。
- 提示词约定：根据给定聊天屏幕、长期目标与摘要，输出 **5 条以内**当下
  最值得推进的即时方向，每条不超过 12 字、动宾短语、互不包含、只输出
  编号行；信息不足时输出 2~3 条泛化方向。解析按行切分、去编号、限长。
- 串行纪律：方向拟定不进 `turnMutex`（不与参谋回合抢队列），但同一时刻
  只允许一个拟定 Job（重复点开收同一结果）。

### 2.4 提示词注入

在 `runAdvisorTurn` 组装 `customSystemPrompt` 时，于最前（风格骨架之后、
briefSection 之前）插入独立段：

```
【本次参谋的即时方向】
先问出对方预算区间。本回合的建议回复必须服务于这个即时方向，
若当前屏幕内容与方向无关，也要指出如何把话题自然引回。
```

两条 LLM 通道（AgentLoop / 精简直连）注入位置一致。未设置方向时整段
省略，行为与现状完全一致。

### 2.5 数据与状态

- `ScreenAdvisor` 新增：
  - `data class DirectionState(val key: String, val selected: String?,
    val suggestions: List<String>, val loading: Boolean)`；
  - `val direction: StateFlow<DirectionState>`（随 `prepareTurn` 解析出的
    会话切换 key：绑定联系人 = `c:<contactId>`，共享会话 = `shared`）；
  - `fun suggestDirections()` / `fun setDirection(text)` / `fun clearDirection()`。
- 持久化（决策点 B 待确认）：推荐仅内存；若选跨次保留，在 `AdvisorPrefs`
  用一个 JSON map（key→方向文本，最近 20 条 LRU）实现，**不做 DB 迁移**。

## 3. 问题③：顶栏紧凑化（单行 + 自动预留位）

### 3.1 现状高度（720×1280 mdpi 模拟器实测口径）

```
拖动把手区        26dp（独立一整条，仅中间 56×4 小横条）
标题行 header     padding 4+8 + 15sp 文本 ≈ 40dp   ← 老参谋 / ✕ 关闭
分隔线            1dp
联系人状态条      padding 6+6 + 12.5sp ≈ 31dp
────────────────────────────
合计              ≈ 98dp
```

### 3.2 新结构（目标合计 ≈ 64dp，省约 1/3）

```
第1行 headerRow（高 38dp，整体作为拖动调高发热区）:
 [≡ 握把 16dp] 老参谋(14sp 粗体)  [方向 ▾ chip]  <弹性空白>
 [自动(置灰)]  [✕]
分隔线 1dp
第2行 联系人状态条（压到 25dp，12sp，上下 padding 4dp，保留不动）
```

- 拖动：视觉小横条取消，改为标题左侧一个「≡」握把图标（新增
  `fb_ic_drag.xml`）；`makeResizeListener()` 从旧 handle 改绑到整个
  `headerRow`（chip/✕/自动各自消费点击，不触发拖动——现有 listener
  return false 即放行子 View 点击）。
- 「自动」：本期渲染为置灰文字按钮，点击 Toast「即将上线」；不写任何
  代发逻辑。后续自动化聊天按 2026-10-14 架构文档实施时，直接把该位换成
  开关键，布局零返工。
- 状态栏文案/点击行为不变（`float_profile_status_*` 两个字符串复用）。

## 4. 问题④：参谋回复一键复制

现状 [TranscriptView.kt](../app/src/main/java/com/verlintas/baic2/floatball/TranscriptView.kt)
的气泡是纯 `TextView`，参谋回复无复制入口。

改造（仅 ASSISTANT 气泡）：

- 气泡由 `TextView` 改为 `FrameLayout` 容器（背景/内边距不变），
  右上角叠一个 22×22dp 的复制图标按钮（新增 `fb_ic_copy.xml`，
  白色线性风格，与 `fb_ic_send.xml` 一致；常态 55% 白，按下全白）。
- 点击：`ClipboardManager.setPrimaryClip(ClipData.newPlainText(...))`，
  复制**纯回复正文**（不带【参谋】前缀，粘进微信可直接用），
  Toast「已复制」。Android 13+ 系统自带复制预览，不额外加动画。
- 流式进行中的临时气泡不显示图标；落库成为正式 ASSISTANT 气泡后出现。
- 用户手动消息与折叠的【屏幕内容】气泡不加复制。
