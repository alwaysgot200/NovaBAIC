# 身份多选与「我的人设」继承方案（2026-10-23）

> 修订 2026-10-23 联系人画像增强的两点口径：①身份从单选改**多选**，入口前移到
> **联系人列表**每张卡片；②「我的侧面」更名「我的人设」，从快照复制改
> **全局人设动态继承 + 联系人补丁**，取消文字自由输入。
> 用户已定口径：继承+补丁 / 列表+详情全部多选 / 新标签先去全局人设库添加。

---

## 1. 需求与口径

### 1.1 身份多选（需求 1）

- 一个人可以同时有多个身份：领导+亲人（你爸兼直属领导）、同事+恋人（办公室恋情）。
- **联系人列表**每张卡片带「身份」下拉，**多选叠加**；详情页快捷下拉、双方人设卡
  身份行**同步多选**（用户选：列表+详情全部多选，全软件一个口径）。
- 多身份在下游的语义 = **并集**：话术召回类目、风格分档判定按「命中任一身份」生效。

### 1.2 「我的侧面」→「我的人设」（需求 2）

- 不让人填文字，全部**点选**；新标签入口 = 全局人设标签库页（用户选）。
- 模型 = **继承+补丁**（用户选）：
  - **默认 = 全局人设**（`self_personas` 全局标签库），动态继承——全局改了所有
    联系人自动跟随；
  - **补丁 = 此关系专属调整**：`extra` 专属补充标签 + `masked` 在此关系里屏蔽的
    全局标签；
  - **生效人设 = (全局库 − masked) ∪ extra**。

## 2. 方案 A：身份多选

### 2.1 数据与词表（advisor 包内，均为本分支自有文件）

- `contact_profiles.identity` 列**不加列不迁库**：改存编码多值
  （`PersonaValues.encodeTags` 同款 JSON 数组，如 `["领导","家人"]`）。
- `StyleVocab` 新增纯函数（保持既有单值函数不动，避免波及面失控）：
  - `encodeIdentities(list): String?` / `decodeIdentities(raw): List<String>`
    ——decode 兼容旧单值（裸字符串 `领导` → `["领导"]`）与畸形输入（防御，不抛）；
  - `normalizeIdentities(raw): List<String>` ——收集输出文本中**全部**词表命中
    （最多 3 个，去重保序，词表外丢弃），供 AI 萃取用；
  - `hasIdentity(raw, id): Boolean` ——判定侧统一入口。

### 2.2 消费面改造清单

| 消费点 | 现状 | 改法 |
| --- | --- | --- |
| `PlaybookRetriever.categoriesForIdentity` | 单身份 → 类目 | 新增 `categoriesForIdentities(list)`：各类目**并集去重**（领导+亲人 → 职场+官场+亲人+通用哲理）；旧函数保留为单值包装 |
| `ChatBriefBuilder` L134 | 传 `profile.identity` | 传 decode 列表走并集召回 |
| `director/TopicStyleRules` L123、`ProactiveStyleTiers` L53 | `identity == LEADER` | `hasIdentity(..., LEADER)`（命中任一即生效） |
| `TopicPlanner` L198 提示行「对方身份」 | 单值 | decode 后「、」连接展示 |
| `TopicEngineStore`/`ProactiveCheckpoint` | 透传 identity 列 | 透传不动（判定侧已收口） |

### 2.3 AI 沉淀链路

- `PersonaExtractor`：`StyleOutput.identity` 仍收模型原文，归一改走
  `normalizeIdentities`（≤3 个）；`SelfFacets.StylePending.identity` 仍是
  `String?`（改存编码多值，JSON 结构不变、旧 pending 数据兼容）。
- 确认语义：**并入**已有多选（不覆盖手动值），与现口径一致。

### 2.4 UI

1. **联系人列表**（`ContactListScreen`/`ContactCard`）：卡片内新增「身份」行——
   已选身份小芯片展示 +「＋设置身份」下拉（多选 FilterChip，点选/取消即落库），
   不点进详情就能改。
2. **详情页快捷下拉**（`IdentityQuickPick`）：单选下拉改多选（弹层内 FilterChip
   多选，显示「领导＋亲人」拼接）；AI 建议采纳 = 并入。
3. **双方人设卡身份行**（`AdvisorPersonaCard.StyleChipRow` 用法处）：单选芯片行
   改多选芯片（选中可再点取消）。
4. 文案：`float_identity_quick_label` →「身份（可多选：领导＋亲人…）」。

## 3. 方案 B：「我的人设」继承+补丁

### 3.1 数据（复用 `selfFacetJson` 列，不迁库）

- 该列改存**补丁对象**：`{"extra":["办事周到"],"masked":["老实"]}`；
- 旧数据兼容（`SelfFacets.decodePending` 同款防御式解码）：
  - 旧 JSON 数组（建档快照/手动标签）→ `{extra: 数组, masked: []}`——
    用户已选标签一个不丢，此后全局新增自动继承；
  - 空/畸形 → 空补丁（纯继承）。
- `SelfFacets` 新增纯函数 `resolve(patchJson, globalTags): List<String>`
  = `(globalTags − masked) ∪ extra`（保序：全局序在前、extra 在后）；
  `encode/decode` 补丁对象编解码进同列。`SelfFacetsTest` 补用例。
- **建档不再快照复制**：`ContactRepository` L152 `facetSeed` 移除（新档案
  selfFacetJson 为空 = 纯继承全局人设）。

### 3.2 UI（`AdvisorPersonaCard` 分区二）

- 标题与口径：「我的侧面（我在我与 TA 的关系里是谁）」→
  **「我的人设（默认用全局人设，可为 TA 专属调整）」**，hint 同步改。
- 布局：
  1. **全局人设**（来自 `self_personas`）：FilterChip 点选——勾=在此关系启用，
     不勾=此关系屏蔽（写 masked）；默认全勾。
  2. **专属补充**（extra）：AI 提案确认进来的标签 + 旧数据换算来的标签，
     带 ✕ 删除。
  3. 「＋添加标签」弹窗**去掉自由输入框**，只留全局库芯片点选（选中=取消屏蔽）；
     想加新标签去「全局人设标签库」页（弹窗内保留一行说明 + 跳转按钮）。
- AI 待确认区不变：提案标签 → 确认进 extra（每关系专属语义）。

### 3.3 下游

- `ChatBriefBuilder.mySectionLines`、`TopicEngineStore`（facetTags）、
  `TopicPlanner`（facets）改调 `SelfFacets.resolve(patch, 全局标签)`；
  全局标签由调用方从 `ContactRepository.selfPersonas()` 注入（resolve 保持纯函数）。
