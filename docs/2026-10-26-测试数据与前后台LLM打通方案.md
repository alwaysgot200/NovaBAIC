## 1. 目标与原则

1. 一条命令把「服务端账号/卡密/LLM 模型」与「客户端联系人画像/策略/白名单」灌好，可重复、可重置。
2. 导入必须**幂等且失败可见**：已存在且未带 `-Reset` → 明确报错并终止（退出码 2），绝不静默覆盖。
3. 真机连接服务器**不依赖 USB**、不依赖手工排查；给出最稳定方案与降级链。
4. App 端 LLM 只选模型：`deepseek-flash`（默认）/ `deepseek-pro`，不填 key、不选官方地址，统一走服务端 LiteLLM。
5. 自动化测试全程免手输：账号 token + 卡密 + 模型一次注入。
6. 所有演示数据只标记/只删除自己的行，不碰真实数据。

## 3. `tests/demo` 目录与脚本设计

```
NovaBAIC/tests/demo/
├── README.md                 # 使用方法、前置条件、故障排查
├── manifest.json             # 上述演示数据的唯一事实源（账号/卡密/联系人/模型）
├── .env.demo.example         # DEMO_SEED_TOKEN / DEMO_DEEPSEEK_API_KEY / 局域网地址
├── net.ps1                   # 连接模式设置（LAN / adb reverse），打印稳定端点
├── seed-server.ps1           # 调 /demo/seed，已存在则退出码 2
├── seed-client.ps1           # 推送 JSON + 触发 debug 导入广播
├── reset.ps1                 # 服务端 demo 行 + 客户端 demo 行精确删除
├── assert.ps1                # 数据/接口/LLM/UI 断言
└── run.ps1                   # 全链路：net → seed → reset? → 注入登录 → 启动 → assert
```

### 3.1 常用命令

```powershell
# 0) 一次性：复制环境变量模板并填写（不要提交真实 key）
Copy-Item .\tests\demo\.env.demo.example .\tests\demo\.env.demo

# 1) 选择连接方式（推荐 LAN；USB 自动化可用 Reverse）
.\tests\demo\net.ps1 -Mode Lan
#   输出并写入：http://192.168.x.x:8080 ；同时确保 adb reverse 作为兜底

# 2) 灌服务端演示数据（已存在会报错终止）
.\tests\demo\seed-server.ps1
#   重置后重灌：
.\tests\demo\seed-server.ps1 -Reset

# 3) 灌客户端本地数据（已存在会报错终止）
.\tests\demo\seed-client.ps1
.\tests\demo\seed-client.ps1 -Reset

# 4) 全链路自动化（导入 → 免登录注入 → 启动 → 断言）
.\tests\demo\run.ps1

# 5) 只做断言（不导入）
.\tests\demo\assert.ps1
```

### 3.2 幂等与失败语义

- 服务端：`demo:v1` 标记存在 + 未 `-Reset` → 脚本检测到固定 demo 账号后打印「演示数据已存在，如需重灌请加 -Reset」并 `exit 2`。
- 客户端：检测 `contactKey` 前缀 `demo:` 或固定 demo 联系人名；存在且未 `-Reset` → 同样 `exit 2`。
- `-Reset` 只删 demo 行：服务端按固定 tenantId/邮箱/卡号/demo 供应商；客户端按 `demo:` 前缀/固定 ID，绝不 `DELETE` 全表。
- 任何一步失败立即停止，不进入下一步（脚本 `$ErrorActionPreference='Stop'` + 显式退出码）。

### 3.3 客户端导入实现（两种，推荐 A）

**A. debug-only 导入入口（推荐）**
- 新增 `app/src/debug/.../DemoSeedReceiver.kt`（仅 debug 源集）：
  - Action `com.verlintas.baic2.DEBUG_DEMO_SEED`
  - `--es path <app 外部文件路径>` + `--ez reset true`
  - 用 `ContactRepository.resolve/recordChannel/updateGoal/setEngagement/update Policy/白名单/自画像` 真实写入；
  - 已有 demo 数据且未 reset → 返回失败（广播结果码 + 日志），脚本据此退出 2。
- 优点：不碰 DB 文件、不受 Room identity hash/WAL 影响，升级后仍可用；release 包不含该入口。
- 推送方式：`adb push manifest.json /sdcard/Android/data/com.verlintas.baic2/files/demo.json`（无需存储权限）。

**B. 预置数据库替换（备选）**
- 从真机 `run-as` 拉 `advisor.db`（含 WAL 合并）→ PC 端 sqlite3 插入 → 推回并删除 `-wal/-shm`。
- 缺点：Room schema 升级后模板易失效；作为离线兜底，不作主路径。

## 4. 网络连接：根因与最稳定方案

### 4.1 根因

- debug 包固定 `server.origin.test=http://127.0.0.1:8080`，手机上的 `127.0.0.1` 只能靠 `adb reverse tcp:8080 tcp:8080` 映射到 PC。
- 无线调试、USB 重插、adb 断线、重启 adb server 都会让 reverse 失效 → App 立即「网络无法连接」。
- PC 侧 nginx 已 `0.0.0.0:8080`，**局域网本身就是通的**，只是 App 没走局域网地址。

### 4.2 三档方案（按稳定性排序）

| 方案 | 稳定性 | 适用 | 要点 |
| --- | --- | --- | --- |
| **A. 局域网 IP（推荐日常）** | 高 | 手机与 PC 同一 Wi-Fi | 构建时注入 `http://<PC局域网IP>:8080`；Windows 防火墙放行 8080 入站；路由器给 PC 固定 DHCP；Android 明文白名单加入该 IP（仅 debug） |
| B. adb reverse（推荐 CI/USB 自动化） | 中 | 有线/无线 adb 在线时 | `net.ps1` 在每次连接后自动 `adb reverse`；断线自动重设；退出时可选清理 |
| C. 公网 HTTPS 测试域（长期最优） | 最高 | 外网/异地/无 adb | 复用生产同构部署（nginx + 证书），如 `test.autojs6.80fafa.com`；App 无需明文白名单，且与生产路径完全一致 |

**落地**：
1. `build.gradle.kts` 支持 `-Pbaic.testOrigin=http://192.168.x.x:8080` 或环境变量 `NOVA_TEST_ORIGIN` 覆盖 `server-config.properties` 的 test 源；
2. `app/src/main/res/xml/network_security_config.xml` 为 debug 增加局域网明文白名单（列表来自 `manifest.json`/构建参数），release 不变；
3. `net.ps1`：自动探测 PC 局域网 IP、检测 8080 可达、按模式写入构建参数、执行 `adb reverse`、最后 `curl /api/v1/health/ready` 验证；
4. App 侧把「网络无法连接」升级为可操作提示：显示当前端点与建议（同网/运行 net.ps1/检查防火墙），并提供「重试」。

**结论（最稳定）**：日常真机用 **A（局域网 IP + 固定 DHCP + 防火墙放行）**；自动化流水线用 **B（reverse 由脚本保证）**；有公网条件后迁移到 **C**。

## 5. App 端 LLM 连接器改造（只选模型）

### 5.1 目标交互

1. 「连接 AI 服务」只剩一张卡：**好参谋云端 AI（推荐）**。
2. 不出现 API Key 输入、不出现官方服务商地址。
3. 模型选择为服务端下发的模型卡片（当前两项）：`DeepSeek Flash`（默认）、`DeepSeek Pro`；数据来自服务端。
4. 凭证自动使用当前绑定卡密（LiteLLM 虚拟 key）；未绑卡 → 引导「绑定卡密」。
5. 卡密绑定成功后自动写入默认 Agent：`baseUrl=${SERVER_ORIGIN}/llm/v1`、`model=deepseek-flash`。

### 5.2 服务端补齐

新增 App 面向的轻量接口（登录态即可，不需要超管权限）：

```
GET /api/v1/point-card/gateway/config
→ { baseUrl: "/llm/v1", defaultModel: "deepseek-flash",
    models: [ { key, displayName, coefficientMilli, coefficientLabel,
                supportsReasoning, modes: [{ key, label, maxTokens }] } ] }
```

- 只返回 `enabled=true` 且 App 可见的模型（`llm_model.appVisible`，默认 true，迁移 + seed 双写）；
- `modes` 由模型 `maxTokens` 派生 Max / 标准 / 精省三档（2026-10-26「AI 服务模型化」需求追加）；
- 不返回上游地址与任何 key；
- 现有超管 `GET /llm/models` 保持不变。

### 5.3 客户端改造点

| 文件 | 改动 |
| --- | --- |
| `feature/agents/AgentWizardViewModel.kt` | 删除官方 Preset 列表与自动识别 key；改为单一 gateway 配置；模型从服务端拉取；默认 `deepseek-flash` |
| `feature/agents/AgentWizardScreen.kt` | 去掉 Key 输入与「或手动选择服务商」；改为服务端模型卡片 + 参数/提示词两步 |
| `core/model/ModelCatalog.kt` | 增加 `deepseek-pro`（替换现有 `deepseek-v4-pro` 的对外名，保留兼容别名） |
| `core/network/provider/ProviderFactory.kt` | 新增 `ProviderId.SERVER_GATEWAY`（或复用 OPENAI_COMPATIBLE + 固定 baseUrl）；Authorization 取卡密 |
| `app/.../account/AccountManager.kt` | `applyGateway` 增加模型参数（默认 flash）；卡密失效（401）时清网关凭证并提示重绑 |
| `app/.../strings.xml` | 新增/替换文案：云端 AI、模型选择、未绑卡提示、卡密失效、额度不足 |

### 5.4 错误映射

| 上游/网关 | App 文案与动作 |
| --- | --- |
| 401 / key 不存在/被冻结 | 「卡密不可用或已停用」→ 跳账号管理重新绑定 |
| 402 / budget 用尽 | 「本卡积分已用完」→ 提示切换下一张/购买 |
| 429 | 「调用过于频繁，请稍后重试」+ 自动退避 |
| 5xx/网络 | 保留离线快照，提示检查网络与端点 |

### 5.5 验收

- 真机：绑定 `sk-DEMOCARD-0001` 后，AI 服务页只出现服务端下发的模型卡片（无「添加服务」、无 key 输入），默认 `deepseek-flash`；
- `curl -H "Authorization: Bearer sk-DEMOCARD-0001" ${ORIGIN}/llm/v1/chat/completions -d '{"model":"deepseek-flash",...}'` 返回 200；
- 切换 `deepseek-pro` 亦 200；
- 解绑/停用卡后请求返回 401 且 App 文案正确。

## 6. 自动化测试机制（免登录/免手输）

1. **登录**：脚本先 `POST /api/v1/auth/login` 取 token（验证码答案走 Redis），再 `am start --es debugToken ...`。
2. **卡密/模型**：扩展 debug 注入：`--es debugCardKey sk-DEMOCARD-0001 --es debugModel deepseek-flash`；
   - 仅 `AccountApi.TEST_LOGIN_ENABLED` 生效；
   - 内部调用 `AccountManager.applyGateway(cardKey)` 并写默认模型，不弹 UI。
3. **数据**：`seed-server.ps1` → `seed-client.ps1` → `run.ps1` 顺序固定；重复运行未 `-Reset` 必失败。
4. **断言（assert.ps1）**：
   - 服务端：账号存在、2 张卡 `userId` 指向该账号、钱包 10000 分、LiteLLM 有 2 个模型与 ≥2 个虚拟 key；
   - 网关：`/llm/v1/models`（带卡密）返回 flash/pro；
   - 客户端：`advisor.db` 中吴瑞曦画像 1 行、渠道 1 行、白名单 1 条、自画像目标=升职加薪；
   - UI：`uiautomator dump` 断言三键存在；打开自动弹层断言出现「吴瑞曦」。
5. **清理**：`reset.ps1` 可只删 demo 行；CI 每次从空 demo 状态开始。

### 11.2 自动档脚本化入口（debug 包）

`DemoSeedReceiver` 新增以下参数（仅 debug 源集，release 不含）：

| 参数 | 作用 |
| --- | --- |
| `--ez auto true` | 走与主页「自动」键相同的 `ACTION_AUTO_FROM_MAIN`：隐藏握手 → `AutoSelectionStore` 选择集 → 单会话陪伴窗口 |
| `--ez stopAuto true` | 走 `ACTION_STOP_AUTO`，停止全部自动 |
| `--es say "..."` + `--es sayContact 吴瑞曦topwayricky` | 模拟来信，走正式 `ScreenAdvisor.submitNotificationTurn` 后台回合 |
| `--es pace "1-3"` | 回复节奏随机区间（秒）；联调快速档 |
| `--es executor a11y\|shizuku\|auto` | 发送通道偏好 |
| `--ei work 60 --ei rest 60` | 工作/停歇段（秒）；`rest=0` 表示不停歇 |

> 广播 `--ez auto` 没有 Activity 生命周期，`AdvisorSelfWindowGate` 会收不到 `onStop`；receiver 在 500ms/1200ms 补两次 `markHidden()`，服务侧在 `SELF_HIDE_TIMEOUT_MS` 内据此继续。这是脚本入口的适配，不改变主页入口的真实握手。
