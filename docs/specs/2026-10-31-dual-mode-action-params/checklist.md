# 验收清单 · 双模式动作分参数（微信 7 步 TDD 用例）

> 依据 spec.md（v3 已批准）。每项验收以代码 / 测试 / 真机证据为准。

- [ ] 同一动作双模式参数分别设计指定：`RpaStep.lineParams` 分线存储（a11y / vision 各自专有参数），JSON/XML/`.rpa` 往返零丢失，旧 JSON 兼容、schemaVersion 过新拒绝导入。
- [ ] 全动作类型参数标准普适：A 公共 / B 载荷 / C 定位（分线）/ D 分线通道四类框架覆盖 18 个动作（spec §一矩阵）。
- [ ] 新建时前置不具备的模式不可选：三芯片恒显示、置灰 + 简洁原因 + 修复入口（不再隐藏）。
- [ ] 编辑动作时模式专有参数灰色不可用：R1（模式不含→整组只读灰）、R2（前置不具备→灰 +「暂不可用」+ 修复入口，就绪自动解灰）。
- [ ] 双模式设计兼容、独立运行：`RpaRunner.run(script, forceLine)` 锁线执行；两线参数互不依赖、互不跨线取值；无静默换线（回退必报 LineFallback）。
- [ ] 前置不具备边界处理（B1–B12）：无微信 App 等 → 运行事件报因 + 提示界面 + 3 秒内干净退出；运行中按动作失败（target_timeout / step_timeout / assert_failed 等）同口径。
- [ ] RPA 脚本导入/导出为文件：JSON / XML / `.rpa` 包（manifest.json + script.json + templates/，sha256 校验）；文件语法逐字段成文（spec §七）；升级兼容 7 条（加字段不升版本、破坏性变更升版本+迁移器、高版本拒绝）。
- [ ] 云端上传：脚本文件上传云备份 / 脚本市场设计成文；云接口可用则上传/下载/再导入全链验证，不可用则记录并只验本地往返。
- [ ] 本地测试全绿：`gradlew :app:testDebugUnitTest :vendor:RPA:test`；`gradlew :app:assembleDebug` 通过。
- [ ] 真机双模式分别跑通微信 7 步夹具（192.168.10.2:41155）：a11y 线与无 a11y 线各自全绿（无回退、屏现「你好」）；B1 边界真机复验。
- [ ] UI 闭环抽查截图存 `tests/tempImg/`：新建置灰变化、动作编辑置灰（a11y 单模式下「无 a11y」组灰）、锁线运行各一遍。
