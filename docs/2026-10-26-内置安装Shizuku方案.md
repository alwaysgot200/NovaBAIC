# 内置安装 Shizuku 方案（2026-10-26）

> 目标：在「好参谋 → 设置 → 权限 → Shizuku」页提供**一键内置安装 Shizuku**：
> 安装包随 App 打包（assets），点击后复制到私有目录并拉起系统安装器，
> 用户在系统弹窗中**手动确认**，装完桌面出现第二个「Shizuku」图标。
> 本文对豆包给出的通用做法逐条核实、纠正，并给出与本仓库现状对齐的落地方案。

## 2. 豆包方案逐条甄别（去伪存真）

| # | 豆包说法 | 结论 | 修正 / 补充 |
| --- | --- | --- | --- |
| 1 | 放 `src/main/assets` | ✅ 正确 | 使用 `app/src/main/assets/`；AGP 自动打包 |
| 2 | 文件名小写、无中文空格 | ✅ 正确 | 统一命名 `shizuku.apk` |
| 3 | 「清单加权限（Android8+ 必须）」 | ✅ 正确但未点名 | 具体是 `android.permission.REQUEST_INSTALL_PACKAGES`（普通权限，**无运行时弹窗**；用户需在系统设置里给本应用开启「允许安装未知应用」） |
| 4 | 检查是否已装 | ✅ 已有能力 | 直接复用 `ShizukuGate.isManagerInstalled()`；再补版本比较 |
| 5 | 检查「允许从此来源安装应用」 | ✅ 方向正确 | 用 `Settings.canRequestPackageInstalls()`（API 26+）判断；未授权时用 `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES` + `Uri.parse("package:$packageName")` 直达本应用开关页（**不是**权限请求弹窗） |
| 6 | 复制 assets 到缓存目录 | ⚠️ 不完整 | 必须：①流式复制到 `cacheDir/shizuku_installer/`；②**原子写**（先 `.tmp` 再 rename）；③校验（长度一致 + `getPackageArchiveInfo()` 包名为 `moe.shizuku.privileged.api` 且 versionCode 可读），失败则重拷并提示 |
| 7 | FileProvider 配置 | ✅ 必需 | minSdk 26，`file://` 会抛 `FileUriExposedException`；provider 必须 `exported="false"`、`grantUriPermissions="true"`、独立 authority（**不要**复用 assists 的 3 个 provider 及其 paths） |
| 8 | 无法静默、必须手动确认 | ✅ 正确 | 无 root/无系统签名时不可绕过；本方案明确“系统安装弹窗 + 用户点安装” |
| 9 | 包体变大 | ✅ 正确 | 实测 +2.45 MB；仅内测分发可接受，上架商店不可行 |
| 10 | 「缓存已存在就不再复制」 | ⚠️ 不够 | cache 会被系统清理，也可能残留半截文件；应做「存在 + 长度/包信息校验通过」才复用 |
| 11 | 版本判断（低于目标自动重装） | ✅ 建议采纳 | 读取内置包 versionCode：已装 **≥ 内置** → 不重装，按钮变「打开 Shizuku」；已装 **< 内置** → 按钮变「升级 Shizuku」 |
| 12 | UI 提示安装完去激活 | ✅ 采纳 | 另补：权限引导、调起成功提示、失败原因、返回页面自动刷新 |

**豆包遗漏、但本仓库必须处理：**

1. `.gitignore` 的 `*.apk` 会把内置包忽略 → 需加 `!app/src/main/assets/shizuku.apk`。
2. 中英文资源必须同步（`tools/check-strings-sync.sh` 强校验）。
3. Shizuku 为 **Apache-2.0**：再分发须保留许可声明，且必须使用**官方签名、未修改**的原版 APK。
4. 现有「去下载 / shizuku.rikka.app」入口在改造后成为死代码，需删除（含 `float_shizuku_download` 文案与 `SHIZUKU_SITE` 常量）。
5. 安装结果不回调 → 用生命周期 `ON_RESUME` 重新探测已装版本，避免用户以为没装成功。
6. 页面上「主操作按钮」与「第一步卡片按钮」当前是两条同义路径，改造后必须统一到同一个安装方法。

## 3. 方案设计

### 3.1 交互流程（状态机）

```
[未安装]
   └─ 点击「安装 Shizuku（内置）」
        ├─ 未授予「安装未知应用」 → 跳系统开关页，页内提示“开启后返回再点一次”
        └─ 已授予 → 准备并校验内置包 → 拉起系统安装器
                       └─ 用户在系统弹窗手动点「安装」→ 桌面出现第二个 Shizuku 图标

[已安装，版本 < 内置] → 按钮「升级 Shizuku」→ 同上流程（覆盖安装，签名须一致）

[已安装，版本 ≥ 内置] → 按钮「打开 Shizuku」→ 直接进入无线调试配对（现有能力）

任意时刻返回本页 → ON_RESUME 重新探测 → 按钮/提示自动切换
```

### 3.4 关键实现骨架

```kotlin
/** 内置安装结果：展示层只映射文案，不解析异常字符串。 */
sealed interface InstallOutcome {
    data object AlreadyInstalled : InstallOutcome          // 已装且版本 >= 内置
    data object PermissionRequired : InstallOutcome        // 需先开启「安装未知应用」
    data class Started(val versionName: String?) : InstallOutcome // 已拉起系统安装器
    data class Failed(val reason: InstallFailure) : InstallOutcome
}

enum class InstallFailure { ASSET_MISSING, ASSET_CORRUPT, LAUNCH_FAILED }
```

```kotlin
// ShizukuInstaller：只做三件事——准备文件、校验、拉起安装器
fun prepareApk(): PreparedApk? = runCatching {
    val dir = File(context.cacheDir, "shizuku_installer").apply { mkdirs() }
    val target = File(dir, "shizuku.apk")
    val assetSize = context.assets.openFd(ASSET).use { it.length }   // 仅供长度比对
    if (!target.isValidCopy(assetSize)) {
        val tmp = File(dir, "shizuku.apk.tmp")
        context.assets.open(ASSET).use { input ->
            tmp.outputStream().use { input.copyTo(it, 64 * 1024) }
        }
        target.delete()
        if (!tmp.renameTo(target)) { tmp.delete(); return@runCatching null }
    }
    val info = context.packageManager.getPackageArchiveInfo(target.path, 0)
    if (info?.packageName != MANAGER_PACKAGE) null else PreparedApk(target, info)
}.getOrNull()

fun launchInstaller(apk: File): Boolean {
    val uri = FileProvider.getUriForFile(context, "${context.packageName}.shizukuinstaller", apk)
    val intent = Intent(Intent.ACTION_VIEW)
        .setDataAndType(uri, "application/vnd.android.package-archive")
        .addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
        .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
    return runCatching { context.startActivity(intent) }.isSuccess
}
```

```kotlin
// 权限判定（API 26+，minSdk 26 直接调用）
if (!context.packageManager.canRequestPackageInstalls()) {
    context.startActivity(
        Intent(Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES)
            .setData(Uri.parse("package:${context.packageName}")),
    )
    return InstallOutcome.PermissionRequired
}
```

```kotlin
// 页面刷新：从系统安装器返回即重查，避免“以为没装成功”
val lifecycleOwner = LocalLifecycleOwner.current
DisposableEffect(lifecycleOwner) {
    val observer = LifecycleEventObserver { _, event ->
        if (event == Lifecycle.Event.ON_RESUME) {

        }
    }
    lifecycleOwner.lifecycle.addObserver(observer)
    onDispose { lifecycleOwner.lifecycle.removeObserver(observer) }
}
```

## 4. 兼容性与边界

| 场景 | 行为 / 说明 |
| --- | --- |
| Android 8.0–16（minSdk 26 / target 36） | `canRequestPackageInstalls`、`ACTION_MANAGE_UNKNOWN_APP_SOURCES` 均原生可用 |
| MIUI / HyperOS | 「安装未知应用」按应用授权；「纯净模式 / 风险应用拦截」可能追加一次系统确认，属系统行为，App 侧只做文案提示 |
| 多安装器 ROM | `ACTION_VIEW` 可能先弹「打开方式」选择器，用户选系统安装器即可（不改用包名硬编码，避免 ROM 差异） |
| 已装非官方签名 Shizuku | 覆盖安装会失败（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）；提示用户先卸载旧包（会丢失其激活状态） |
| 下载站包与内置包同版本 | 同名同签名，可直接覆盖；版本比较以 versionCode 为准 |
| 系统清理 cache | 每次点击重新做长度/包信息校验，不通过即重拷，不依赖“缓存存在” |
| 静默安装 | 不支持（无 root、无系统签名），系统弹窗必须由用户确认 |
| 上架应用商店 | 不建议：内置第三方 APK 通常违反商店政策（本应用当前不上市，仅内测分发） |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `.gitignore` 忽略内置包 | 他人拉代码后打包缺包，安装必失败 | 加 `!app/src/main/assets/shizuku.apk` 例外，并在 PR 检查 `git status` 包含该文件 |
| 用户未开「安装未知应用」 | 点击后无反应（旧版本可能静默失败） | 前置 `canRequestPackageInstalls()`，未授权先跳设置并就地提示，返回再点 |
| 复制过程被中断 | 半截 APK 导致解析失败 | 原子写 + 长度/包名校验；失败给明确文案并重试 |
| ROM 安装器不认 content:// | 安装器打不开 | 已用 `FLAG_GRANT_READ_URI_PERMISSION`；极端场景提示改用官网下载（仅提示，不再内置官网按钮） |
| 设备已装更高版本 | 误降级/覆盖失败 | 版本比较：已装 ≥ 内置则只提供「打开」，不触发安装 |
| Shizuku 升级维护遗漏 | 内置版本落后，用户装到旧版 | 维护 SOP（见 §7）+ CHANGELOG 记录内置版本 |
| 许可合规 | Apache-2.0 再分发要求保留声明 | 使用官方原版未修改 APK；在 `docs/THIRD_PARTY_NOTICES`（或现有许可说明处）登记 Shizuku 版本 + Apache-2.0 |

## 7. 维护 SOP（Shizuku 升级）

1. 从官方 GitHub Release 下载新 APK（**不得修改/重签**）。
2. 替换 `app/src/main/assets/shizuku.apk`，保持文件名小写。
3. 记录新 versionCode/versionName 与 SHA-256 到本文件或 CHANGELOG。
4. `aapt2 dump badging` 确认包名仍为 `moe.shizuku.privileged.api`。
5. 跑构建 + 真机验证「升级」路径（旧版 → 新版覆盖安装）。
6. 若上游改变签名（极少见），必须在文案中提示用户先卸载旧版。

## 8. 备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **A. assets + FileProvider + ACTION_VIEW**（本方案） | 代码量小、跨 ROM 稳定、无网络依赖 | 无安装结果回调（用 ON_RESUME 补偿）；多安装器 ROM 可能弹选择器 | **采用** |
| B. `PackageInstaller.Session` | 无 FileProvider、可拿到精确安装结果 | 需运行时广播接收器、各 ROM 安装 UI 差异、代码与坑更多 | 暂不采用，作为后续增强备选 |
| C. 在线下载安装 | 不增加包体 | 首次安装依赖网络与官网可达性；与“免去下载麻烦”目标相悖 | 不采用 |
| D. 引导用户去应用商店 | 合规 | 中国大陆商店未必有 Shizuku，体验不可控 | 不采用 |
