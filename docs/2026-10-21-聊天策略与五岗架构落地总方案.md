## 七、子代理协作机制与权限分配（2026-10-21 应用户要求收口）

### 7.1 协作机制（四条铁律 + 交接物契约）

1. **单线指挥**：好参谋大脑（ScreenAdvisor）是唯一编排者；五岗之间**禁止横向互调**，
   一切调用沿回合管线单向流动——杜绝网状依赖与循环等待。
2. **提案-执法分离**：烧 LLM 的岗位只能「提案」（哨官判定、军师许可、代言者稿件）；
   放行/拦截/发送只在纯代码执法面（审查官词表 + 执行器官危险等级门）强制执行。
   模型永远不是执法者。
3. **快慢车道解耦**：快车道（哨→军→代→审→执）同回合串行、用户可感知；档案官走
   慢车道异步（萃取节流/互斥锁），绝不阻塞回合。
4. **预算纪律**：每回合 LLM 典型 2 次（代言者+审查官）、**上限 4 次**；哨官词表
   短路零成本、军师 90s 缓存、档案官慢道不计入回合。

**交接物契约**（数据只沿管线传递，字段即合同）：

| 交接物            | 产出     | 消费          | 关键字段                                               |
| ----------------- | -------- | ------------- | ------------------------------------------------------ |
| 感知包            | 感知器官 | 哨官          | 文本/图像/来源（a11y/截图/投影）/置信                  |
| SentryVerdict     | 哨官     | 大脑→军师     | 场景（CHAT/UNCERTAIN/NON_CHAT）+ 敏感面标记 + 红线初筛 |
| **Permit 许可单** | 军师     | 代言者+审查官 | approach 方针 + 三维逐档许可 + within + needsHuman     |
| 稿件 Draft        | 代言者   | 审查官        | 文本 + 所引用的 Permit 版本号                          |
| GatekeeperVerdict | 审查官   | 执行器官      | pass / veto(reason) / downgrade / askHuman             |
| 台账记录          | 各岗     | 档案官        | director*logs 键值（含 tactic*\* 系）                  |

**故障降级**（任何岗位失效不得中断回合）：军师超时/畸形 → 无许可单，仅手段库段
（保守路径）；哨官轻 LLM 失败 → 保守判 NON*CHAT；审查官 LLM 失败 → 纯函数规则兜底；
执行失败 → 上报大脑 + 必要时 E1 问主人。错误一律 reason 字符串（`REASON*\*`）。
