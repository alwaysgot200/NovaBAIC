## 0. 结论先行

### 0.1 推荐方案

1. **主扇形菜单保持 6 项**：单次 / 连续 / 自动 / 主页 / 更多 / 退出。
   不新增第 7 个「RPA」子球，不修改 `offsets`、`solveFan`、180°/30° 这套既有几何。
2. 三个 RPA 工具放进「更多」卡片菜单，并分成两组：
   - **RPA 工具**：布局分析 / 以图找图 / RPA 设计；
   - **设置与帮助**：设置 / 帮助 / 好参谋设置 / 联系人画像 / 关于。
   RPA 组置顶，卡片复用 `CappedScrollView` 限高滚动，避免 8 行 + 分组头超出屏幕。
3. **布局分析 = AutoJs6 风格的 a11y 全屏覆盖层**：
   先隐藏悬浮球与「更多」卡片，抓取目标 App 的当前帧 + a11y 窗口树，再用
   `AssistsWindowManager` 的 `TYPE_ACCESSIBILITY_OVERLAY` 挂全屏覆盖层；画面是冻结帧，
   上面画绿色控件框与绿色小标签，点控件弹出 AutoJs6 式白色竖排菜单，菜单里可看属性、
   看层级、复制定位 JSON、隐藏节点/同框节点、切换窗口、退出；刷新时先摘覆盖层、
   抓新帧新树、再挂回。**这个工具必须开启 a11y**。
4. **以图找图 = 透明全屏结果浮层**：
   选一张本地图片 → 隐藏自身窗口抓当前屏幕 → OpenCV 多尺度匹配 → 在透明全屏覆盖层上
   画绿色命中框、十字中心、像素坐标与归一化比例；不依赖 a11y，使用 Shizuku / 录屏帧源。
5. **RPA 设计 = 脚本库 + 每项运行图标 + 后台运行服务**：
   每个脚本卡片旁有一个运行图标，点击直接执行，不跳编辑器；运行交给
   `RpaRunService` 前台服务 + `RpaRunController` 状态流，切到微信后继续跑，通知栏可停止；
   运行期间隐藏悬浮球，避免它进入视觉抽帧。
6. **编辑器 = 单列步骤流 + 动作库底部抽屉 + 属性面板**：
   补齐可见插入线、边缘自动滚动、触觉反馈、撤销、步骤卡摘要与 kebab 菜单；
   `LAUNCH_APP` 支持系统应用选择器；`RpaStep` 新增 `delayAfterMs`（执行后等待）；
   DUAL 每个定位动作仍强制 a11y + vision 两套定位。
7. **Demo 只做测试夹具，不发行**：微信 7 步流程（启动微信 → 点搜索 → 输入联系人 →
   点联系人 → 点输入框 → 输入「你好」→ 点发送）放在 `app/src/test`，供开发期反复
   跑通；发行版不出现 Demo 卡片、菜单、字符串或示例脚本，新建脚本只生成空白骨架。
8. **修复一个现有真问题**：当前 `RpaInspectorScreen` 在 `RpaActivity` 里抓帧抓树，
   实际分析的是 RPA 自己，不是目标 App；v4 改为「全局工具 + 编辑器拾取回填」，不再在
   编辑器里现场分析自己。
9. **悬浮球靠边自动隐藏**：空闲且贴边时 2.5s 后滑出屏幕，只留约 10dp 可点边条；
   点边条/横向拖动即滑回完整球。忙碌、录制、自动、菜单/分屏/方向弹层及 RPA 运行期间
   一律不隐藏；RPA 运行期间由 `RpaChromeGate` 直接摘球。

### 0.2 历次修正表

| 主题 | 早期设计 | 当前定稿（v4） | 原因 |
|---|---|---|---|
| 入口 | 主菜单第 7 项「RPA」 | **取消**；主菜单保持 6 项 | 用户明确不要 RPA 子悬浮菜单 |
| 扇形几何 | 7 项、180°、相邻 30° | **不动** 现有 6 项 `-75°…+75°` | 降低回归风险，入口改由「更多」承担 |

| 找图结果 | 透明全屏结果浮层 | **保留** | 用户已确认 |
| 列表运行 | 列表内运行面板 | **每项一个运行图标**，点击直接执行 | 用户澄清“就是执行这个 RPA” |
| 运行生命周期 | 编辑器内 `rememberCoroutineScope` | `RpaRunService` 前台服务 + 状态流 | 离开编辑器 / 切到微信后不能停 |

| 编辑器定位 | 内嵌分析器 / 找图页自抓当前画面 | **全局工具拾取 + 自动回填 + 剪贴板兜底** | 修复“分析自己”的 bug |
| 悬浮球 | 常驻贴边 | **Idle 贴边 2.5s 自动收起，留 10dp 边条；点/拖滑出** | 用户要求平时靠边自动隐藏 |
| 行业调研 | 无 | 新增 §7.3 拖拽交互调研 | 用户要求 |

### 0.3 四条不变铁律

1. **模式先行**：脚本级 `A11Y / VISION / DUAL`；模式决定属性面板哪些卡可用、哪些必须双写。
2. **双线路必须显式**：DUAL 下每个需要定位的动作必须同时配置 a11y 与 vision；
   运行时优先 a11y，失败写入 `LineFallback` 后粘性切 vision；禁止静默换线。
3. **运行前过就绪门**：`RpaReadiness` 有 ERROR 不执行；工具页不可用时只在自己页面报原因，
   不影响悬浮球其它入口。
4. **Demo 不发行**：示例流程、示例数据、生成入口与相关字符串只能存在于 test source set；
   正式包的新建脚本只提供空白骨架。

### 4.5 悬浮球靠边自动隐藏

**目标**：平时不挡内容，需要时一触即出；不改变现有单击/双击/长按/拖动手势。

#### 4.5.1 触发条件

| 条件 | 必须满足 |
|---|---|
| 状态 | `Mode.IDLE` |
| 位置 | 球逻辑坐标距左/右屏缘 ≤ 24dp（取更近的一侧） |
| 遮挡 | 无扇形菜单、无卡片菜单、无分屏、无方向弹层 |
| 计时 | 最后一次移动/菜单关闭/状态回到 Idle 后 2500ms |
| RPA | 不在 RPA 运行期；运行期由 `RpaChromeGate` 摘球，不进入本逻辑 |

不满足任一条即取消计时；球在屏幕中间时永不自动隐藏。

#### 4.5.2 收起形态

- 收向更近的左右侧，窗口滑出屏幕，只留 **10dp** 边条；
- 窗口 `params.x` 允许越出屏幕，需给主球窗加 `FLAG_LAYOUT_NO_LIMITS`；
- **逻辑坐标 `ballX/ballY` 不变**，只改窗口可视 x；恢复、旋转、重建球时都用逻辑坐标；
- 动画 180ms、减速插值；动画期间不写 `ballX`；
- 不改变球大小、颜色、徽章；不新增第二个“边条窗”。

#### 4.5.3 滑出与手势

| 用户动作 | 行为 |
|---|---|
| 点边条 | 只滑回完整球，**不展开扇形菜单**；随后重新计时 |
| 从边条横向拖动 | 先滑回，再进入原有拖动；拖动落点按逻辑坐标计算，避免从藏起位置跳变 |
| 双击边条 | 第一击只滑回；该次触摸序列不触发连续参谋 |
| 长按边条 | 第一击只滑回；该次触摸序列不触发单次参谋 |
| 菜单/分屏/RPA 启动 | 先强制滑回并取消计时 |

实现上在 `ACTION_DOWN` 记录“本次是从收起态唤醒”，该序列内所有手势回调直接吞掉，
只做滑回；`ACTION_UP/CANCEL` 后重新计时。

#### 4.5.4 与既有状态机共存

- 忙碌 `ONESHOT`、录制 `RECORDING`、自动 `AUTO`：立即滑回并禁止收起；
- `onConfigurationChanged`（旋转/分屏）：用逻辑坐标重钳，取消当前收起；
- `hideAllOverlays()` / 服务销毁：取消计时与动画，不残留 Runnable；
- 菜单展开/卡片弹窗期间不收起；关闭后重新计时；
- 不做持久化：重启服务后按 `ballX/ballY` 重建，再按当前是否贴边重新计时。

#### 4.5.5 文件与验收

- 纯几何与常量：`app/.../floatball/FloatEdgeTuck.kt`（可单测）；
- 计时、动画、窗口更新、手势唤醒：`FloatBallService`；
- 单测：`app/src/test/.../floatball/FloatEdgeTuckTest.kt`。

验收见 §12.1；关键回归是“收起后点击仍能展开菜单”和“四角/横屏不跑位”。

### 5.2 形态选择：为什么是覆盖层，而不是 Activity

用户问“抓帧沉浸页 + 刷新”和“实时全屏悬浮层”是什么效果。先把三个概念说清：

| 形态 | 实际效果 | 问题 |
|---|---|---|
| 抓帧沉浸 **Activity**（v1） | 启动一个全屏 Activity，把截图铺满，框画在截图上 | Activity 一启动，目标 App 就退到后台；刷新只能抓到自己；编辑器里的分析器甚至分析 RPA 自己 |
| 实时跟随 **悬浮窗** | 持续抓树/重绘，跟随目标 App 滚动 | 与 a11y 快照语义冲突，全屏持续触摸，复杂度和误触高 |
| **a11y 全屏覆盖层（v4）** | 目标 App 仍在前台；覆盖层显示冻结帧 + 框；刷新时短暂摘层再抓目标 | **与 AutoJs6 视觉一致**；刷新语义正确；无“自己分析自己” |

因此 v4 采用 **a11y 全屏覆盖层**，但画面是“刷新时刻的冻结帧”，不是逐帧实时。
“实时”只体现在刷新后重新抓取；这与 AutoJs6 的布局分析体验一致。

### 5.3 技术形态

- 用 `AssistsWindowManager.add(view, params)` 挂一个全屏经典 View；
- `params` 基于 `AssistsWindowManager.createLayoutParams()`：
  - `type = TYPE_ACCESSIBILITY_OVERLAY`；
  - `width/height = 屏幕宽高`，`gravity = TOP|START`；
  - 保留 `FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS`；
  - `format = RGBA_8888`，`alpha = 1`；
  - API 28+ 设置 `layoutInDisplayCutoutMode = SHORT_EDGES`（如 WMS 仍裁切，再补 `FLAG_LAYOUT_NO_LIMITS`）；
- **不修改 Assists 上游**；覆盖层由 app 侧 `RpaAnalyzeOverlayController` 管理；
- 覆盖层用 **经典 View**，不用 `ComposeView`：
  - 项目内没有服务/浮窗托管 Compose 的先例；
  - 覆盖层需要自管 LifecycleOwner / ViewModelStoreOwner / SavedStateRegistryOwner；
  - 分析器 UI 是画布 + 菜单 + 列表，经典 View 足够，风险更低；
  - Compose 仍用于 `RpaActivity` 与透明找图 Activity。

### 5.4 抓取流水线

```
点击「更多」→「布局分析」
  → 检查 a11y：AssistsService.getOrNull() != null 且 a11yBridge.connected
      ├─ 未就绪：显示「需要无障碍」notice 卡片（去开启 / 取消），不抓帧
      └─ 就绪：
           1. 门禁：Mode.IDLE；前台包名不是本 App（否则提示先切到目标 App）
           2. closeSplit(keepBall = true) + hideAllOverlays()
              → 撤分屏/菜单/卡片；analyze != null 期间 showBall/restoreBall 直接返回
           3. 等 2 帧 + 180ms（SETTLE_MS），确保上一轮覆盖层/球从合成层移除
           4. 采集同一代快照（RpaAnalyzeCapture.capture）：
              - frameSource.grabFrameWithFreshness()   // a11y 截图优先，投影/Shizuku 兜底
              - windows = AssistsCore.getAccessibilityRootNodes(AllWindows)
                  · 过滤空包名/自身包名；按 root 读取扁平快照
                  · 聚焦窗口移到首位，activeWindowIndex 按前台包名映射
                  · 节点预算 1200、深度上限 64
           5. RpaNodeIndex.build(windows, activeWindowIndex, maxNodes = 800)
           6. RpaAnalyzeOverlayView 挂到 AssistsWindowManager（isStack = true, isTouchable = true）

```

要点：

- 帧与节点树在同一轮 `capture()` 内采集；刷新时先摘覆盖层再重抓，避免两套时间点错位；
- 覆盖层挂上后，目标 App 的触摸被覆盖层消费，不会误点目标 App；
- 覆盖层是 a11y 窗口，刷新时**先摘掉**再抓，避免把覆盖层自己抓进去；
- 悬浮球与卡片在采集前必须移除，避免进入截图或节点树；
- 若截图失败但节点树成功：深色底 + 框照常显示，工具条提示“截图不可用，仅显示节点框”；
- 若节点树为空：工具条提示“当前窗口没有可读节点”，不静默降级 OCR；
- 若 a11y 在覆盖层打开期间被关闭：`FloatBallService` 订阅 `a11yBridge.connected`，
  断开即 toast + `close()`，恢复悬浮球。

### 5.6 节点索引与 JSON 生成

```kotlin
    companion object {
        fun build(windows: List<RpaAnalyzeWindow>,
                  activeWindowIndex: Int = 0,
                  maxNodes: Int = 800): RpaNodeIndex
    }
    fun window(index: Int): RpaAnalyzeWindow?
    fun nodesOf(windowIndex: Int): List<RpaAnalyzeNode>
    fun boxNodes(windowIndex: Int, exclude: Set<Int> = emptySet()): List<RpaAnalyzeNode>
    fun hitTest(x: Int, y: Int, windowIndex: Int, exclude: Set<Int> = emptySet()): RpaAnalyzeNode?
    fun sameBounds(a: RpaAnalyzeNode, b: RpaAnalyzeNode): Boolean
    fun path(node: RpaAnalyzeNode): List<RpaAnalyzeNode>
    fun pathText(node: RpaAnalyzeNode): String
    fun hasSelector(node: RpaAnalyzeNode): Boolean
    fun toSelector(node: RpaAnalyzeNode): String       // 定位 JSON
    fun toA11ySpec(node: RpaAnalyzeNode): String
    fun toSnapshot(node: RpaAnalyzeNode): String
    fun toNodeJson(node: RpaAnalyzeNode): String
    fun toA11yJson(): String                          // 整页 a11y 快照
}
```

- `build`：先序遍历扁平化，index / 父索引 / 深度 / 窗口索引；节点上限夹取；
- `hitTest`：包含该点、面积最小；面积相同取更深节点；跳过不可见 / disabled / 被隐藏；
- `toA11ySpec` 的生成优先级：
  1. `viewId`（最稳定）；
  2. `description`；
  3. `text`；
  4. `className`（附 `clickableOnly` / `editableOnly`）；
  - `snapshot` 始终带上；
  - 若四类都为空，返回 null：该节点只能复制节点 JSON，不能生成稳定选择器；
- JSON 序列化手写转义（`"`、`\`、换行、制表、控制字符），避免引入额外依赖；
- 生成示例：

```json
{
  "selectors": [
    { "description": "搜索", "textMatch": "CONTAINS", "enabledOnly": true }
  ],
  "pick": "FIRST",
  "action": "CLICK",
  "snapshot": {
    "packageName": "com.tencent.mm",
    "className": "android.widget.ImageView",
    "description": "搜索",
    "bounds": { "left": 980, "top": 120, "right": 1040, "bottom": 180 },
    "clickable": true
  }

```

### 5.7 与现有编辑器分析器的关系（修复自分析 bug）

## 6. 以图找图：透明全屏结果浮层

### 6.1 用户流程

```
更多 → 以图找图
  → 选择图片（系统 Photo Picker）
  → 阈值（0.50–0.95，默认 0.80）/ 灰度（默认开）
  → 点「查找」
  → 隐藏自身窗口 → 抓当前屏幕 → OpenCV 多尺度匹配
  → 透明全屏结果层：绿色命中框 + 十字中心 + 中心像素坐标 + 归一化比例 + 得分
  → 重新查找 / 复制视觉定位 JSON / 关闭
```

拾取模式额外有「应用到当前步骤」。

### 6.2 “透明全屏结果浮层”的准确语义

- Activity 主题 `Theme.Translucent.NoTitleBar`（参考 `FloatCaptureActivity`）；
- 结果层**不把截图当背景**，目标 App 仍然可见；只画：
  - 绿色命中框；
  - 十字线 + 中心点；
  - 底部结果卡（坐标/比例/得分/按钮）；
- 匹配用的抓帧只在内存里做坐标换算，不铺到屏幕上；
- 结果是一个“抓帧瞬间”的静态位置：覆盖层消费触摸，目标 App 不会因误触而变；
  但目标 App 自身动画/通知可能导致画面变化，所以结果卡标注“抓帧时刻”，
  并提供「重新查找」；
- 关闭结果层即回到目标 App。

### 6.3 状态机

```
PICK
  ├─ 选择图片（PickVisualMedia，无需存储权限）
  ├─ 阈值滑杆 / 灰度开关
  └─ [查找]（未选图时禁用）

SEARCHING
  ├─ decorView.alpha = 0f
  ├─ 等 2 帧 + 120–180ms
  ├─ device.visionConfigFrame()   // Shizuku 优先，MediaProjection 兜底
  ├─ 恢复 alpha = 1f
  └─ RpaTemplateMatcher.bestMatch / find（Dispatchers.Default）

RESULT
  ├─ 透明全屏：绿框 + 十字 + 底部卡
  └─ [重新查找] [复制 RATIO] [复制视觉定位 JSON] [应用到步骤] [关闭]

ERROR
  ├─ 无截图源 → 提示 + 「打开 Shizuku 授权页」「授权录屏」
  ├─ 图片解码失败 → 保留已选图，允许重选
  ├─ 模板比帧大 → template_larger_than_region
  └─ 低于阈值 → 显示最佳得分，不画假框
```

### 6.4 抓帧时不把自己抓进去

1. 点击「查找」后，把 Activity 的 `decorView.alpha = 0f`（不是 `GONE`，避免窗口重建）；
2. 等 2 帧 + 120–180ms，确保合成层不再绘制本 Activity；
3. 调 `device.visionConfigFrame()`：
   - 优先 Shizuku `screencap`；
   - 无 Shizuku 回退 MediaProjection；
   - 两者都没有 → ERROR，不拿空白图硬匹配；
4. 抓帧成功后恢复 alpha，再匹配；
5. 悬浮球：P3 实际实现为**进工具即隐藏、退出即恢复**（服务侧 `quickFindActive`
   标志），而不是只在抓帧瞬间隐藏。理由：本页消费全屏触摸，球若留着既点不到、
   又会在自隐抓帧时被一起抓进帧里；P4 引入 `RpaChromeGate` 后再收敛为按需隐藏；
6. 不使用 a11y 截图，保持“无 a11y 视觉线路”的感知面与执行面一致。

### 6.5 匹配与坐标

复用 `RpaTemplateMatcher.bestMatch / find`：

- 多尺度 `ImageScales.FACTORS`；
- 灰度/彩色通道与帧一致；
- alpha 掩膜支持透明 PNG；
- 阈值治理：低于阈值不返回命中；失败消息带最佳分数；
- `CvMatch` 提供 `left/top/width/height/centerX/centerY/score`。

结果坐标同时给两份：

1. **抓帧像素**：`中心 (cx, cy)`；
2. **归一化比例**：`(cx / frame.width, cy / frame.height)`，
   可直接生成 `RpaVisionLocator(kind = RATIO)`。

- 绿色框按 `frame` → 当前根 View 的宽高分别缩放（x、y 独立比例），
  避免状态栏/导航栏导致的比例误差；
- 结果卡同时显示“抓帧时刻”，提示结果不是实时跟随。

### 6.6 模板与回填

| 模式 | 行为 |
|---|---|
| 独立快捷找图 | 不写 `filesDir/rpa`；临时图放 `cacheDir/rpa/quickfind/selected.png`，退出删除 |
| 编辑器拾取 | 点「应用到步骤」时：把选中的 PNG 通过 `store.saveTemplate(scriptId, templateId, png)` 写入脚本模板目录；生成 `RpaVisionSpec(primary = TEMPLATE(templateId), fallback = RATIO(cx, cy))`，写入 `RpaPickResult` |
| 未命中 | 不显示「应用到步骤」；可「仅保存模板」，让用户之后在编辑器里调整阈值/区域 |

- 模板生成后，运行时用同一个 `RpaTemplateMatcher`，保证“快捷工具能看到”与
  “脚本运行时能找到”的口径一致；
- 不需要新增持久化模板库；模板按 `scriptId` 隔离。

  7 步微信流程只在 test source set，见 §7.9。

### 7.2 后台运行：`RpaRunService` + `RpaRunController`

**现状问题**：编辑器 `startRun()` 用 `rememberCoroutineScope` + `DisposableEffect`，
离开编辑器/Activity 销毁即取消。列表运行必须独立于页面生命周期。

新增：

```kotlin
@Singleton
class RpaRunController @Inject constructor() {
    sealed interface State {
        data object Idle : State
        data class Running(
            val scriptId: String,
            val scriptName: String,
            val stepIndex: Int,
            val stepCount: Int,
            val stepLabel: String,
            val line: RpaLine?,
            val startedAt: Long,
        ) : State
        data class Finished(
            val scriptId: String,
            val scriptName: String,
            val ok: Boolean,
            val detail: String,
        ) : State
    }

    val state: StateFlow<State>
    val events: StateFlow<List<RpaRunEvent>> // 最近 200 条
    fun start(script: RpaScript)
    fun update(...)
    fun finish(...)
    fun reset()
}
```

```kotlin
@AndroidEntryPoint
class RpaRunService : Service() {
    @Inject lateinit var device: RpaAndroidDevice
    @Inject lateinit var store: RpaScriptStore
    @Inject lateinit var controller: RpaRunController
    @Inject lateinit var chromeGate: RpaChromeGate

    // ACTION_START + scriptId / ACTION_STOP
    // onCreate: 建通知渠道；startForeground 立即挂“准备运行”
    // start: 读取脚本 → 校验 + RpaReadiness → RpaRunner.run → 更新 controller/通知
    // 结束/异常: controller.finish → stopForeground → stopSelf
    // onDestroy: cancel job；确保 controller 回到 Idle、chromeGate 释放
}
```

运行语义：

1. 列表点运行 → `RpaValidator + RpaReadiness`；有 ERROR 弹问题列表与授权入口，不启动服务；
2. 无 ERROR → `startForegroundService`，通知栏显示“RPA 运行中 · 脚本名”；
3. 通知栏 action「停止」→ `ACTION_STOP` → cancel job → 状态 `Finished(ok=false, "stopped")`；
4. 服务运行期间 `RpaChromeGate.hide("run")`，悬浮球隐藏，避免：
   - 悬浮球进入视觉抽帧；
   - a11y 节点树把悬浮球当业务控件；
   - 用户误触悬浮球打断流程；
   结束后 `show("run")` 恢复；
5. 切到微信/其他 App 后继续执行；`RpaActivity` 可在后台被销毁，状态仍在单例；
6. 前台服务类型 `specialUse`，manifest 与 `FloatBallService` 同款：
   `foregroundServiceType="specialUse"` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`；
7. Android 13+ 通知权限被拒时，服务仍可运行，但列表/页内要提示“通知不可见”；
8. 同一时间只允许一个运行；再次运行先确认停止；
9. 编辑器运行也走同一个服务：先保存脚本，再启动服务；编辑器只观察状态与日志；
10. 服务 `START_NOT_STICKY`，进程被杀后不自动重跑，避免不可控。

#### 7.3.2 提炼出的手机端规则

1. **不照搬桌面三栏**。手机用：单列步骤流 + 底部动作库抽屉 + 属性底部面板；
2. **点击添加 + 长按拖入**双通道：
   - 点击动作库 = 追加到末尾（快）；
   - 长按拖入 = 精确插入（可见插入线）；
3. **插入线、自动滚动、触觉反馈、撤销**是拖拽的四个基本盘：
   - 没有插入线，用户不知道会插到哪；
   - 拖到屏幕上下边缘要自动滚动；
   - 长按开始/经过新插入点给触觉；
   - 插入/移动/删除给 Snackbar 撤销；
4. **属性编辑在上下文里**：点步骤 → 属性面板；不做常驻第三栏；
5. **定位是独立子流程**：画面/控件树/找图器是“拾取器”，不是普通表单；
   手机端要做“从目标 App 拾取”，而不是让用户手填坐标；
6. **运行/调试靠近列表**：每个脚本有运行图标；运行中高亮当前步骤；
   日志在编辑器内可折叠，不常驻占半屏；
7. **“执行后等待”是一等字段**：自动精灵把它放在动作参数里，
   用户不需要为了等 5 秒额外插一个 WAIT；
8. **不做代码生成**：手机端生成“定位 JSON”比生成脚本更实用；
9. **录制器后置**：先把“动作 + 双线路定位 + 运行”闭环做稳，录制是下一阶段。

| 操作 | 手势 | 反馈 |
|---|---|---|

实现要点：

1. **可见插入线**：不再只在标题旁显示“插入到第 N 步”，而是在目标 gap 画
   2dp 强调色横线，贯穿列表宽度；
2. **自动滚动**：拖动位置进入列表顶部/底部 64dp 区域时，每帧 `scrollBy` 约 8dp；
3. **触觉**：拖动开始 `LongPress`，插入点变化 `TextHandleMove`（API 级兜底）；
4. **撤销**：维护 `ArrayDeque<List<RpaStep>>`，最多 20 个结构快照；
   只记录插入/移动/删除/复制，属性字段修改不进入撤销栈，避免噪音；
5. **拖拽影子**：跟随手指的浮层，显示动作名/步骤名；原步骤降到 35% 透明度；
6. **运行中禁用**：拖拽、插入、删除、开关全部禁用；当前步骤高亮并滚动到可见；
7. **无障碍**：`⋮`/运行/停止/撤销都有 `contentDescription`；
8. **自动保存**：结构变更 600ms 防抖保存；点运行/返回立即保存；

### 7.7 执行后等待 `delayAfterMs`

模型增量：

```kotlin
@Serializable
data class RpaStep(
    val id: String,
    val action: RpaAction,
    // ...existing...
    val delayBeforeMs: Long = 0,
    val delayAfterMs: Long = 0, // 新增：动作成功后等待
)
```

- UI：属性「基础」区显示「执行前等待」「执行后等待」；
- 范围 0–60000ms，越界钳制，负值不允许；
- 快捷 chip：0 / 1s / 3s / 5s；
- 引擎：在 `StepFinished(ok=true)` 之后、下一步之前 `delay(delayAfterMs)`；
  失败/重试期间不执行；`onFailure = CONTINUE` 的失败步骤也不执行；
- 旧 JSON 无该字段 → 默认 0，schemaVersion 仍为 1；
- 保留独立 `WAIT` 动作，用于“与上一步结果无关”的显式等待；
- 测试夹具第 1 步使用 `LAUNCH_APP(delayAfterMs = 5000)`，不再额外插 `WAIT`。

### 7.8 编辑器拾取模式（解决“目标 App 不在前台”）

这是本方案对原始需求“屏幕元素定位交互配置”的关键补齐。

```
编辑步骤 → 点「布局分析拾取」/「以图找图拾取」
  → 保存脚本
  → RpaPickCoordinator.arm(scriptId, stepId, kind)
  → RpaActivity.moveTaskToBack(true)
  → Toast：已进入拾取；请切到目标 App 的目标画面，
          从悬浮球 → 更多 → 布局分析 / 以图找图
  → 用户在目标 App 导航到目标画面
  → 打开工具：
      - 布局分析覆盖层 / 以图找图 Activity 检测到 armed 请求
      - 顶部显示“为「脚本名」第 N 步拾取 a11y/vision 定位”
  → 点「应用到当前步骤」
      - 生成 RpaA11ySpec 或 RpaVisionSpec
      - 拾取模式保存模板到脚本目录（vision）
      - RpaPickCoordinator.deliver(result)
      - 工具关闭/覆盖层退出
      - 用 FLAG_ACTIVITY_REORDER_TO_FRONT | SINGLE_TOP 回到 RpaActivity
  → 编辑器打开对应步骤的属性面板，显示“已回填”
```

- `RpaPickRequest`：`requestId / scriptId / stepId / kind / scriptName / stepLabel / createdAt`；
- `RpaPickResult`：`requestId / scriptId / stepId / kind / a11ySpec? / visionSpec? / templateId?`；
- 请求 15 分钟过期；工具里可「取消拾取」并清空；
- 结果同时写 `cacheDir/rpa/pick/<requestId>.json`，防进程被杀；
- `RpaActivity` 加 `launchMode="singleTop"`，`onNewIntent` 消费结果；
- 若 `RpaActivity` 已被销毁，新建后按 `scriptId` 从 store 载入、定位到 `stepId`；
- 模式不匹配时工具只做独立查看，不显示“应用”：
  - A11Y 脚本不能拾取 vision；
  - VISION 脚本不能拾取 a11y；
  - DUAL 两种都可；
- 如果用户不想走拾取：编辑器仍可「从剪贴板导入 JSON」；
  全局工具独立使用时提供「复制定位 JSON」。

> **P4b 落地偏差（2026-10-27）**：最终没有 `RpaPickResult` 文件与
> `onNewIntent` 消费；工具直接写 `RpaScriptStore` 后带
> `EXTRA_SCRIPT_ID/EXTRA_STEP_ID` 重开 `RpaActivity`。编辑器拾取入口用
> `finish()` 而不是 `moveTaskToBack(true)`（跨任务 `REORDER_TO_FRONT` 在真机
> 不可靠），因此回跳总是新实例。完整清单见 §7.11。

### 7.14 布局分析器加固与 Assists / AssistX 调研（2026-10-28）

#### 7.14.1 采集链路确实复用了 Assists

分析器不是「自己另造一套截图 + 猜测控件」：`RpaAnalyzeCapture` 在**抓帧之后**于主线程
调用 `AssistsService.getOrNull()`，通过 `service.windows` 枚举 `AccessibilityWindowInfo`
（失败回退 `rootInActiveWindow`），并用 `AssistsCore.getPackageName(AllWindows)` 找前台
包名；每个 `window.root` 再按预算（1200 节点 / 深度 64）手写遍历成 `RpaRawNode`。
之所以不用 `AssistsCore.getRootNodeTree()`：它的 `NodeTree` 缺 `isEditable`，且递归
没有深度/数量上限，深 WebView 会拖死主线程。**节点本身来自 Assists 的无障碍服务**，
这与 `vendor/assists/simple` 的 `ScrollContacts`（`findByText("通讯录")` +
`findByTags("android.widget.ListView")` + `scrollForward()`）是同一条通道。

#### 7.14.2 AssistX（`e:\_android_work\assistsx`）调研结论

- 它是**插件宿主**：`assistsxkit` 用 WebView + NanoHTTPD 承载页面，依赖
   `assists-base / mp / web / ime / log 3.5.9`，本身不是布局分析器；
- `A11yJavascriptInterface` 只暴露 `isA11yEnabled` / `openAccessibilitySetting`，
  **没有可视化布局分析 UI**，也没有「点控件出框」的命令；
- 节点能力在 `assists-web` 的 `ASJavascriptInterface` / `CallMethod`，配合
  `NodeCacheManager`（`SoftReference` + `nodeId`）把节点句柄交给 JS 侧复用；
- 可学的不是界面，而是两点：① 官方 `assists_service.xml` 的服务配置；
  ② 用「服务单例 + NodeTree/NodeCache」作为唯一节点出口，UI 只做渲染。

因此本项目继续保留「Assists 采树 + 自绘覆盖层」的分工，不引入 AssistX 的 WebView 布局。

> （`com.google.android.marvin.talkback/*`）**，与触摸探索（TE）状态无关。
> 当日 A/B 矩阵（`uiautomator dump` 采微信前台窗口）：仅好参谋 / +autojs
> 白名单桩 / +桩且框架 `touchExplorationEnabled=true`（dumpsys 确认）→ 均
> 381 字节空根摘树；+「随选朗读」SelectToSpeak（TE=**false**）→ 92,695 字节 /
> 272 节点全树（含「通讯录」）；+TalkBack（TE=true）→ 94,354 字节 / 277 节点
> 全树。开↔关在同一微信进程内秒级实时生效。10-28 记录的「TE=true → 272 节点」
> 里真正起作用的是当时启用列表里出现了 marvin 服务，TE 只是伴随变量——下文
> 「TE 放行」的因果归因错误。dex 静态取证的「autojs 白名单 ID /
> `isTouchExplorationEnabled`」两条件在运行时均不成立，疑被微信 Tinker 热补丁
> `patch-5a32c721`（logcat artd 证实运行时加载）改写检查。
>
> 由此的处置变更：
> - **主路线改为 `WechatTreeUnlock`**（`app/.../floatball/auto/WechatTreeUnlock.kt`）：
>   分析会话级临时启用「随选朗读」（TalkBack 家族里副作用最小的载体：不开 TE、
>   不朗读全文、无常驻浮窗），退出分析配对还原；树可读或用户已开家族服务时
>   零改动，自动通道不可用时 toast 报因引导手动开启；
> - **白名单桩弃用**：`dev/build-a11y-whitelist-stub.ps1` 已标 DEPRECATED，
>   不再构建/安装（运行时无效）；
> - **`TouchExplorationGate` 降级为兜底**（且本 ROM 运行时 setServiceInfo 是
>   空操作，实际不可用）；`flagRequestTouchExplorationMode` 静态常开方案维持
>   禁令（2026-10-29 性能事故）。
>
> 下文 10-28 的旧结论保留作取证历史，不再作为设计依据。

**根因不是本项目配置，而是微信 8.0.79 的主动反自动化**。静态反编译
`classes8.dex` 的 `com.tencent.mm.sdk.platformtools.b.c()`（smartDisableAccessibility）：

1. `getEnabledAccessibilityServiceList(FEEDBACK_SPOKEN)` 中若含微信可信白名单
   组件（`HashSet` 18 条固定 ID，含
   `org.autojs.autojs/com.stardust.autojs.core.accessibility.AccessibilityService`）→ 放行；
2. 否则 `AccessibilityManager.isTouchExplorationEnabled()==true` → 放行；
3. 否则反射 `AccessibilityManager.setStateLocked(0)` 关闭自身进程无障碍 →
   `rootInActiveWindow` 空根（`uiautomator dump` 381 字节）。

真机 A/B 取证（微信 8.0.79 / Android 15，2026-10-28）：仅本服务时 381 字节空根；
触摸探索打开后 93,198 字节 / 272 节点（含「通讯录」）；TE 开↔关在**同一微信进程
内秒级实时开合**，无需重启微信。`uiautomator dump` 同样空根，排除分析器自身问题。

Assists/AssistsX 能分析微信的原因即在此：官方 `assists_service.xml` 的
`accessibilityFlags` 含 `flagRequestTouchExplorationMode`（AssistsX 的
`assists_service_simple.txt` 更是 `canRequestTouchExplorationMode="true"`），
服务绑定即请求触摸探索 → 微信放行。双方节点 API 完全同源（`rootInActiveWindow`
+ `findAccessibilityNodeInfosBy*`），无微信专用通道；Simple 的
`ScrollContacts`/`GestureBottomTab` 即 `findByText → findFirstParentClickable().click()`
+ `findByTags(ListView/RecyclerView) → scrollForward()` + 节点中心手势点击。

**修复（已落地并真机验证）**：

- `device/impl/.../accessibility_service_config.xml` 增加
  `android:canRequestTouchExplorationMode="true"`（能力位 0x2，提交带 `[upstream-touch]`；
  `flagIncludeNotImportantViews` / `typeWindowsChanged` 等此前补齐项保留）；
- 新增 `TouchExplorationGate`（app/floatball/auto）：acquire/release 可重入脉冲，
  `setServiceInfo` 置/清 `FLAG_REQUEST_TOUCH_EXPLORATION_MODE`，用户原开
  （TalkBack）不代关；只包「采集快照 / 脚本执行」等无人操作短窗口——触摸探索期
  全局触摸变「先探索后激活」，不能照抄 Assists 的常开；
- `RpaAnalyzeCapture` 退化重采：先正常采集，仅节点树 <2 节点时脉冲解锁重采，
  普通应用零开销；
- `AssistsA11yBridge.clickText/scrollList` 照搬 Simple 的微信对象链（自带脉冲门）；
- 仪器测试 `TouchExplorationGateDeviceTest` 锁定整条链路。

## 10. 就绪、权限与错误矩阵

| 工具/运行 | 必需 | 可选 | 不可用时 |

## 11. 风险与回归控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 覆盖层尺寸/裁切 | 框错位/工具栏不可点 | 用 `createLayoutParams` + `FLAG_LAYOUT_NO_LIMITS`；`SHORT_EDGES`；真机四角/刘海/横屏验收 |
| 覆盖层无焦点 | 返回键不可用 | 工具条/菜单提供「退出」；与 AutoJs6 一致 |
| 覆盖层挂上后抓到自己 | 框错位 | 刷新先摘层、等 2 帧 + 150ms、再抓 |
| a11y 节点树过大 | 卡顿 | 最多 800 节点；标签最多 120；碰撞剔除 |
| 同一代快照 | 帧/树时间点不一致 | `generation` 校验；同一刷新批次采集 |
| a11y 服务中途断开 | 覆盖层消失、球不恢复 | `RpaChromeGate` 检测 `AssistsService.getOrNull()==null` 时释放；`finally` 清理 |
| 找图抓到自己 | 匹配到弹框 | alpha=0 + 2 帧 + 120–180ms；抓帧前 gate 隐藏球 |
| 找图结果漂移 | 框与实时画面不一致 | 结果卡标注“抓帧时刻”；覆盖层消费触摸；提供重新查找 |
| 无截图源 | 找图不可用 | 明确就绪门 + Shizuku/录屏入口 |
| 运行服务前台限制 | 启动 5s 内未 startForeground 崩溃 | 先把“准备运行”通知挂上，再加载脚本 |
| 运行期间球进入抽帧 | 误匹配 | `RpaChromeGate` 全运行期隐藏球；通知栏停止 |
| 运行服务被杀 | 状态残留 | `onDestroy` 取消 job、controller 回 Idle、gate 释放；`START_NOT_STICKY` |
| 列表运行读到未保存脚本 | 运行旧版本 | 返回/运行前强制保存；列表只读 store |
| 编辑器拾取请求过期 | 回填失败 | 15 分钟过期 + 工具提示；结果写 cache；Activity 重建可恢复 |
