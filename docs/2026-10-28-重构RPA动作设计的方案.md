### 4.2 步骤新字段（`RpaStep`）

## 五、自定义动作与条件：三层能力（v5 定案 = 决策⑨）

> **定案（用户确认「设计很好」）**：**对大多数用户，「复合动作 + 公式条件」比写 JS 更方便**——零代码、
> 可校验、可复用；JS 不删除，降级为高级兼容层（沙箱）。**不引入 Lua/自研语言**（它们都不比 JS 普及，
> 只会多一套学习成本）。

| 层                | 能力                                                                                                                                     | 用户门槛 | 批次                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------- |
| L1 复合动作（宏） | 把一段步骤**组合命名**为一个动作，带参数（变量），供任意步骤引用；可随 `.rpa` 包分发                                                     | 零代码   | 阶段1 模型/引擎，阶段2 UI |
| L2 公式条件       | 运行条件用**类 Excel 公式**：`count >= 3 && hasImage("btn")`；白名单函数（`var/hasImage/hasText/prevOk/random/now`），静态校验、无副作用 | 零代码   | 阶段1                     |
| L3 沙箱 JS        | 自动精灵同款 JS 表达式（图9 兼容）与自定义钩子                                                                                           | 会写 JS  | 后续批次                  |

**L3 沙箱边界（后续批次，先定）**：Rhino（纯 JVM 无 JNI；实施前复核 MPL-2.0 与 GPL-3.0-or-later 兼容）；
API 白名单桥 `getVar/setVar/hasImage/hasText/random/log`；**禁网络、禁文件 IO、禁反射与类加载**；
单次求值超时 200ms；含代码的 `.rpa` 包导入时二次确认；无沙箱的自由脚本一律不提供（§十一）。

**复合动作约束**：定义存 `RpaScript.customActions`（名称 + 步骤组 + 参数声明）；执行时参数代入 +
递归展开，**嵌套深度 ≤ 3**；跳转目标不得跨复合动作边界（校验器拦截）；循环用 `repeat`/条件跳转表达，
复合动作内不做循环语法。

## 六、执行引擎（`vendor/RPA/.../engine/RpaEngine.kt`）

1. **handler 注册表（裁定⑧）**：`executeOnce` 的 `when` 分发重构为 `Map<RpaAction, RpaActionHandler>`
   注册表；引擎循环只认注册表，**新增动作类型零改循环**；未注册（P2 占位）→ 显式
   `unsupported_action`。注册表完备性有单测兜底（每个枚举值或有 handler、或显式列入 unsupported）。
2. **程序计数器循环**：`while (pc in steps.indices)`；`CONTROL_FLOW` 改写 `pc`（stepId → 下标在运行前
   一次性解析成跳转表）；受双保险约束：`MAX_JUMPS = 1000` + 既有 `DEFAULT_RUN_TIMEOUT_MS` 运行预算，
   超限 `jump_limit_exceeded` 收口。整脚本 `global.repeat` = 外层循环（重置 PC，同样受预算约束）。
3. **条件求值**：`RpaStepCondition` → 求值器接口（阶段1 实现 L2 公式 + 结构化条件；后续批次挂 L3 沙箱，
   同一接口替换）。**求值异常一律按「条件不满足」处理并记原因日志，绝不崩引擎、绝不静默**。
4. **repeat**：`repeat = 总执行次数`；每次执行都先过运行条件；任一次失败走 `onFailure`/`retries` 既有
   逻辑；与 `retries` 在日志中分字段标注。
5. **复合动作**：`COMPOSITE` 步骤展开执行（深度 ≤3，参数代入）。
6. **全局默认等待**：步骤 `delayAfterMs == 0` 且 `global.defaultWaitSec != null` 时取全局值；
   `stopOnFailure = true`（默认）遇失败即停。
7. **`RpaDevice` 端口增量最小化**：新动作里只有 `OPEN_LINK` 需要新设备能力（新增 `openLink(url)`）；
   `SET_VARIABLE`/`CONTROL_FLOW`/`COMPOSITE` 纯引擎内部；点击三兄弟全部复用既有
   `tap/longPress/locate`。端口不膨胀 = app 侧实现面不膨胀。
8. 就绪门 `RpaReadiness`（`RpaCatalog.kt` 内）前置不变（A11Y 查无障碍；VISION 查 Shizuku+投影+OCR），
   跳转/条件/重复均记运行日志。

### 7.9 两大工具能力复用架构（v5 定稿 = 决策⑩/⑬）：布局分析 · 以图找图

**定位（先排矛盾）**：「RPA 布局分析」（`analyze/` 覆盖层）与「以图找图」（`quickfind/`）是两个已实现
的工具，但它们**不是独立功能孤岛，而是 RPA 设计的感知与拾取引擎**。悬浮球菜单里的工具入口未来可能
移除——**RPA 流程不得依赖任何菜单入口**，一律通过能力组件与「直拉」调用使用它们。

#### 7.9.1 复用映射（工具能力 → RPA 触点，全部已实现，只接线不重造）

| 工具能力（已实现）                          | RPA 设计中的用途                                                       |
| ------------------------------------------- | ---------------------------------------------------------------------- |
| 布局分析覆盖层：节点树浏览/点选/选择器生成  | **节点拾取**：a11y 定位「...」→ `armPick(A11Y)` → 写回 `RpaSelector`    |
| 布局分析：`RpaNodeIndex` / 节点快照          | `RpaA11ySpec.snapshot` 布局快照、校验器定位警告引用                     |

#### 7.9.2 点击图片完整链路（决策⑩：图片拾取 → 以图找图）

**用户流**（动作编辑浮窗内「点击图片」步骤）：

1. 「图片位置」行提供**双入口**（替换现有「...」只进找图面板的单入口）：
   - **「图片拾取」（主推）**＝ `armPick(VISION)` **直拉**以图找图拾取模式 → **屏幕拾取**（冻结帧、
     方形/圆形选区、实时尺寸、最小边 8px 校验，圆形走 `RpaQuickFindPicker` 透明掩膜）→「使用此区域」
     → 模板写 `store.saveTemplate`、`RpaVisionSpec(TEMPLATE)` 回填（既有 `applyPick` 桥）→ 编辑浮窗
     自动恢复并定位该步，**缩略图即时可见**；
   - **「找图面板（精调）」**＝现 `RpaVisionScreen`（图11）：ROI 拖框裁剪 / 相似度 50–99% / 匹配第几 /
     快速搜图 / 兜底定位。
2. **验证**：图11 面板右上「**从屏幕测试找图**」补齐（对齐参考）——抓当前帧跑 `device.testTemplate`，
   结果画布复用以图找图展示件：绿色命中框 + 白十字中心 + **中心坐标 chip `(x, y)`** + 尺寸标签；
   面板内同帧「测试」按钮保留。
3. **回编辑浮窗**：图片位置行显示模板缩略图 + 摘要（如 `相似度 76% · 匹配第 1`）；「确定」写 `RpaStep`。
4. **运行时**：`TAP + TEMPLATE Target` 既有链路，命中后注入点击（按下时间/holdMs 照旧），
   失败按 `onFailure`/`retries` 既有语义。

**复用清单（禁止重复造轮子）**：`RpaQuickFindGeometry.frameRect/circleBoundingSquare`（坐标映射）、
`RpaQuickFindPicker`（裁剪 + 圆形掩膜）、`RpaTemplateMatcher`/`device.testTemplate`（多尺度匹配）、

**报因**：抓帧失败、选区过小、匹配无命中、模板写盘失败均沿用既有文案**显式报因**，不静默。

### 7.10 P2 能力的「规划中」置灰与显式报因规范（v5 成文 = 决策⑪）

| 场景 | 行为 |
| --- | --- |
| 动作类型下拉（点击颜色 / 多指手势 / 录制等 P2 项） | **置灰 +「规划中」徽标**，不可选中；保留位置让用户看到路线图（置灰禁用 ≠ 假入口） |

## 八、存储与导入导出（决策① 定案）

- **内部事实源 = JSON**（`filesDir/rpa/scripts/<id>.json`，原子写，不双写）。
- **导出三选一**：`.json` / `.xml` / `.rpa`（完整包）；**导入自动识别**全部三种。
- `RpaScriptCodec`（接口）+ `RpaJsonCodec` + `RpaXmlCodec`（内置 `XmlSerializer/XmlPullParser`，
  零新依赖，字段与 JSON 一一对应；密封条件类型按 tag 序列化）。
- `.rpa` 包 = `manifest.json`（format / schemaVersion / exportedAt / name / sha256 / scriptCode 标记）+
  `script.json|xml` + `templates/*.png`（模板按 templateId 命名，条件与定位共享同一模板池）；
  导入复用 `duplicate()` 的「模板先落、脚本后落、失败回收」防孤儿策略（`RpaScriptStore.kt`）。
- 导入语义 = **新建脚本文档**（id 冲突自动取新 id，不做合并）；含 P2 能力（JS/点击颜色/多指）的脚本
  可导入可编辑，对应步骤标「需升级」徽标，运行到该步显式报因（§六-1）。
- 单文件 `.json/.xml` 导入：引用模板的步骤给警告不阻断。`.rpa` 即未来「上传/下载动作脚本」的
  市场交换格式（服务端对接不在本期）。
