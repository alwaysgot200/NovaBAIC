# 投影免弹窗授权方案（Shizuku + appops）

## 0. 一句话

通过 Shizuku（shell 权限）执行一次 `appops set com.verlintas.baic2 PROJECT_MEDIA allow`，
MediaProjection 授权从此静默通过——无障碍关闭时的感知降级路径（投影抓帧 + OCR）**零弹框**。
本机 HyperOS / Android 14+ 真机已全链路实测验证（§2）。

## 1. 背景与问题

- AGENTS 教训 2：Android 14+「一授权一投影」，老参谋「拍完即关」策略下每次单击都要弹投影授权框。
- 无障碍开启时感知走 a11y 文本/截图，零弹框；但 RPA 双模铁律（AGENTS §4.5）要求 **a11y 关闭时也能走通**，此时感知只能落投影路径——弹框成为体验断点。
- 用户诉求：不开无障碍时，RPA 依靠 **Shizuku + 静默 MediaProjection + OCR + 以图找图** 完成。

## 2. 实证记录（2026-10-21，HyperOS 真机）

| 步骤 | 命令/操作 | 结果 |
| --- | --- | --- |
| 1 | `adb shell appops set com.verlintas.baic2 PROJECT_MEDIA allow` | 设置成功 |
| 2 | `settings put secure enabled_accessibility_services ''`（关 a11y，强制走投影） | a11y 确认关闭 |
| 3 | 悬浮球长按 → 菜单点「问答」 | **全程零授权框** |
| 4 | logcat | FloatCaptureActivity 启动后一帧即关（透明中转无感）→ 投影 FGS 静默建立 → 抓帧 → 投影立即释放 → `OCR process succeeded` |

机制：AOSP 授权 Activity 检查到 `PROJECT_MEDIA` appop 已 allow 时直接放行，不显示对话框。
appop 状态持久（重启不清）；ROM 恢复出厂/大版本升级可能重置，由设置页状态自查兜底（§5.4）。

## 3. 用户流程（设置页引导）

入口：老参谋设置 → 权限分区新增一行「**投影免弹窗授权**」，三态显示：

```
未装 Shizuku        → [去安装]（应用市场或官网下载 Shizuku）
Shizuku 未运行      → [启动引导]（无线调试配对，见 §4）
未授权              → [一键授权]（通过 Shizuku 执行 appops 命令）
已生效              → 绿色状态条「投影授权已静默」+ [重新执行]（ROM 重置后自愈）
```

## 4. 无线调试配对引导（精简文案，两步前置 + 三步配对）

> 直接写进引导页的最终文案（strings.xml，float_* 前缀）：

**前置（一次性，决定成败）：**

1. 开发者选项 → 打开「**USB 调试（安全设置）**」。它与普通「USB 调试」是**两个独立开关**，
   不开它，配对成功后执行命令仍会权限不足。
2. 设置 → 通知 → 通知显示设置 → 切换为**原生 Android 样式**。国产 ROM 的自定义通知
   会吞掉 Shizuku 的配对弹窗，6 位配对码出不来，卡在「正在搜索配对服务」。

**配对：**

1. Shizuku 内点「通过无线调试启动」→ 跳转开发者选项 → 打开「无线调试」
2. 无线调试 → 「使用配对码配对设备」，记住弹出的 6 位码
3. 回 Shizuku 输入配对码 → 启动成功

## 5. 技术实现

### 5.1 依赖（[upstream-touch] 最小侵入）

- 版本目录追加 `shizuku-api` / `shizuku-provider`（`dev.rikka.shizuku`）；
  `app/build.gradle.kts` 引用。两处均为纯追加，提交带 `[upstream-touch]` 标记
  （AGENTS §4.2 尾部三问：外部库无法在 app 模块内绕过）。

### 5.2 新增文件（全部在 app 模块 floatball 包）

| 文件 | 职责 |
| --- | --- |
| `floatball/shizuku/ShizukuGate.kt` | Shizuku 三态检测（已装/运行中/已授权）+ `appops set/get` 执行与解析（`Shizuku.newProcess`） |
| `floatball/shizuku/ShizukuGrantScreen.kt` | 引导页（Compose，复用 `AdvisorPage` 骨架 §4.4：返回箭头 + 标题 + 分步引导 + 三态按钮） |
| `FloatSettingsActivity.kt`（改现有） | 权限分区追加一行入口 + 状态跳转 |

### 5.3 状态机

```
sealed ShizukuState {
    NotInstalled          // 引导下载
    InstalledNotRunning   // 无线调试配对引导（§4 文案）
    RunningNotGranted     // [一键授权] → Shizuku.newProcess("appops set ...")
    Granted               // 绿色状态 + [重新执行]
    ExecuteFailed(reason) // 展示 shell stderr 原文（权限不足 → 指回前置第 1 步）
}
```

- 授权执行：`Shizuku.newProcess(arrayOf("appops", "set", "com.verlintas.baic2", "PROJECT_MEDIA", "allow"), null, null)`
- 状态自查：`appops get com.verlintas.baic2 PROJECT_MEDIA` 输出含 `allow` 即生效
- Shizuku 运行检测：`Shizuku.pingBinder()` + `Shizuku.checkSelfPermission()`（v13 API）

### 5.4 投影链路零改动

FloatCaptureActivity 中转保留（Android 14+ 投影必须 Activity 发起）——appop 生效后它一帧即过；
ScreenAdvisor「拍完即关」策略不变（投影仍一授权一投影，只是授权静默化）。无障碍仍是感知首选，
本方案只补强 a11y 关闭场景。

## 6. 验收标准

1. 全新设备走完引导 → a11y 关闭 → 单击问答零弹框（logcat 见投影静默建立 + OCR 成功）
2. 设置页三态显示正确；ExecuteFailed 展示 shell 原文并指回前置引导
3. 不装 Shizuku 时既有功能不受影响（入口显示说明文案）
4. `tools/check-license-headers.sh` 过 + 编译过 + 冒烟链路过 + logcat 无崩溃

## 7. 边界与风险

- **ROM 差异**：appop 静默放行是 AOSP 授权 Activity 的检查逻辑，HyperOS 实测通过；
  其他 ROM 未逐一实测——设置页提供「重新执行」+ 状态自查兜底，失败展示 shell 原文。
- **权限不足**（前置第 1 步没开）：shell stderr 会含 `SecurityException`/`not allowed`，
  ExecuteFailed 文案直接指向「USB 调试（安全设置）」。
- **持久性**：appop 由系统 AppOpsService 持久化，重启不清；恢复出厂/刷机会丢 → 引导页状态自查，丢了一键补上。
- **隐私口径不变**：帧只进内存不落盘、零遥测（本地优先红线）。
